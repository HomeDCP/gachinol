## 순서 판정 기준 — 사전식 사다리 (점수 합산 금지)

위에서부터 걸리면 그 자리에서 결정한다. **논쟁 여지를 없애는 것이 목적이다.**

| 단 | 질문 | 근거가 된 실패 |
|---|---|---|
| **L0** | 선행이 **실구동**으로 충족되는가? (타입·픽스처·테스트만 있는 건 구동 아님) | 후보 중 여럿이 착수 불가였다 |
| **L-obs** | **이것이 없으면 다른 모든 판정이 무의미한 계측기인가?** | 빌드 스탬프 0건이라 "배포된 것이 어느 커밋인가"를 물을 수 없었다 · 대장 판정 도구가 대장 아닌 행을 센다 |
| **L1** | **지금 사용자에게 도달하는 경로가 끊겨 있는가?** | 인터넷 502 · 배포 안 된 라우트 호출 · 번들 placeholder |
| **L2** | **실발생·재발 가능 결함인가?** (기능 부재와 구분) | #168 영구 교착 |
| **L3** | **MVP 한 바퀴의 미보유 조각인가?** (계획에 태스크조차 없는 것 포함) | 카카오 게시자산 0줄 |
| **L4** | 시니어 기자가 실제로 쓸 수 있게 하는가? | 사용자 정의 서비스 목적 |
| **L5** | 나머지 — **순서표가 아니라 백로그에 둔다** | |

같은 L 안에서는 **규모 작은 순**. 그 둘로 순서가 결정된다.

> ⚠️ **`L-obs`는 2026-08-31 독립 검증에서 신설됐다.** 원래는 빌드 스탬프(#186)를 L1로 적었는데,
> 검증자가 *"빌드 스탬프 부재는 도달 경로를 끊지 않는다 — ROOT-CAUSE 자신이 '수리가 아니라 계측기
> 복구'라고 적어 결함이 아님을 자인한다"*고 지적했다. **맨 앞에 두는 판단은 옳았고 L 라벨이 틀렸다.**
> ⭐ 더 중요한 지적: 검증 전 QUEUE는 **단계 번호와 L이 거의 완전히 일치**했다 —
> *"사다리로 단계를 정한 것이 아니라 단계로 L을 붙였다"*는 서명이다. **L 칸을 결과에 맞춰 채울 수
> 있으면 사다리의 목적(논쟁 여지 제거)이 무효화된다.** 아래 배치는 그 지적을 반영해 재정렬한 것이다.

**동반 의무 D1**(규율 23): 착수하는 결함이 *"검사 밖이라서 생긴 것"*이면 **그 검사 축을 넓히는
작업을 같은 슬라이스에 포함**한다. 순서에 넣으면 항상 뒤로 밀리지만 동반 의무면 반드시 같이 간다.

**두 부정 명제**: "미착수 = 곧 후보"가 아니다(L0 통과해야 후보) · "오검출 = 곧 후보"도 아니다.

⚠️ **선행 칸에는 "기능 의존"만 적는다.** 같은 파일 중복 편집을 피하려는 "순서 분리"는 **차단이 아니다**
(부록 A 참조). 이 구분을 놓쳐 검증 전 QUEUE가 선행 4건을 과잉 기재했다.

## 현재 상태를 아는 법 (값을 적지 않는 이유)

```bash
git fetch origin main && git log --oneline -1 origin/main   # 기준 커밋
gh pr list --state open                                     # 열린 PR
node infra/scripts/daejang-recheck.mjs                      # 대장 대조(pending) — 상태 칸 "미수신"으로 시작하는 행만 대상
node infra/scripts/daejang-recheck.mjs --all                # 대장 대조(감사) — 상태 칸 보유 표 전건 대상
#  ⚠️ 대장 #182 해소(2026-09-01)로 "대장 아닌 표까지 함께 센다"는 舊 결함은 수리됐다 — **다만 "믿어도
#  된다"로 뒤집지 않는다.** pending 모드는 표 무결성·행 추출이 §6-1~§6-11 전 구간(259행, §6-11의 물리
#  분절 표 포함)을 정확히 잡지만, **판정 자체는 여전히 대장 원문의 재현 명령·기대값 정확성에 의존한다.**
#  `--all`(감사 모드, 상태 칸 무관 전건)은 **이미 해소된 행도 함께 재는데**, 그런 행은 등재 당시 기대값과
#  현재값이 다른 게 정상(해소했으니 값이 바뀌었다)이라 "어긋남"으로 뜰 수 있다 — 그건 이 도구의 결함이
#  아니라 감사 모드의 설계된 동작이다(해소 후 값 변화를 잡아내는 것이 감사의 목적). 요약: **행 추출·표
#  무결성은 신뢰 가능. 판정(일치/어긋남/수동)은 여전히 사람이 대장 맥락과 함께 읽어야 한다.**
pnpm --filter @gachinol/shared build && pnpm --filter @gachinol/api test   # api 기준선
```

**진행률 판정**은 구현 커밋(`feat|fix|refactor|perf`)에 태스크 ID가 등장하는지로 한다.
⚠️ 오검출을 뺀 뒤에 판정한다 — **원값 불변이 진척 없음을 뜻하지 않는다**(오검출로 이미 매치되던
태스크를 실제로 구현하면 원값이 안 움직인다).
