#### 감점 1 — **Y2-1(최중대)**: 02 §C "Lighthouse CI 게이트"가 태스크·비범위 선언 어느 쪽에도 없다(무기록)

02 §C 성능 예산 표(정본)의 3번째 행:

> `| **Lighthouse CI 게이트**(모바일, **구독자 앱 한정** …) | Performance ≥ 80, Accessibility ≥ 95 | CI 주간 측정 | 2주 연속 미달 시 … |`

같은 절의 부기가 **"이 CI 게이트(Performance ≥ 80·Accessibility ≥ 95, 병합 차단)는 구독자 앱 단독이 대상"**
이라 못박는다. 그리고 02 §E-18(=E2 §F-1 라벨 18)의 원문은 **"CI installability 구조 검사(매니페스트 필수
필드·서비스워커 등록·HTTPS, §C 성능 예산 표 반영)"** 로, §C를 명시 수신한다.

그런데 실행계획 전체에서 이 게이트를 **산출물로 소유하는 태스크가 없다**:

E2-work-breakdown.md:253  T-W1-11b 행 — 02 §E-18 인용문 안의 "§C Lighthouse 게이트 범위 확정과 동일 근거"
E5-quality-gates.md:80    "성능 예산 판정 지연" 행으로 이관             (미달 시 조치 서술)

세 히트 전부가 **참조·서술**이고 산출물 결박은 0건이다. E2 T-W1-11b(라벨 18 매핑 태스크)의 산출물 열은
`CI installability 구조 검사 + CI 번들 예산 게이트 + CF 캐시 퍼지 CI 스텝` 3요소이며 Lighthouse 게이트가 없다.
E2 §0 비범위 선언 8항목에도 없다.

이는 이 계획이 **스스로 4회 닫아 온 유형의 4회차**다 — D8-1(02 §E-9 "CI 자동 실행" 요소 → T-W2-17 신설),

D14-1/J-6(02 §B `scenes.tsx` → T-W2-18 신설). 특히 E2 §0이 D8-3을 인용해 **"어느 쪽이든 무기록 상태만은

#### 감점 1 — **Y2-3(중대)**: §C-2 9행이 "문자 그대로 승격"을 주장하나 E5 §B와 문안이 전혀 다르다

E5 §B "문서 산출물 태스크" 행의 실제 문안:

> "**게이트①**: 산출물의 DoD 항목별 자가 대조 체크 + 내부 링크·인용 대상 실재 grep(각 1회).

**두 문안은 공통 어절이 없다.** 재현:

```
$ grep -c "산출물의 DoD 항목별 자가 대조 체크" E1-agents-org.md          → 0
$ grep -c "T-NC-13 판정 명령①②의 사전 자가 실행" E5-quality-gates.md      → 0
# 대조군 — 한 라운드 전에 같은 형식으로 신설된 8행(CI 설정)은 문자 그대로 일치
$ grep -c "변경 diff의 잡 구조 자가 체크(잡 이름·`needs` 순서·`continue-on-error` 유무·required 대상 여부)" \
    E1-agents-org.md E5-quality-gates.md                                → E1:1 / E5:2
```

즉 이 계획은 8행에서는 "문자 그대로 승격"을 실제로 지켰고, 9행에서만 지키지 않은 채 지켰다고 적었다.

(E5 §B) / 반영 문안(E1 §C-2 9행)이 3자 모두 다르다.**

**실행상 파급**: E1 §B-1 표준 템플릿의 작업 순서 4항은 "**E5 §B 명령 표의 해당 대상 행을 실행**"이라
지시한다(라운드 18 V2-11 일반화). 따라서 문서 산출물 태스크를 발주하면 구현 에이전트는 §B-1을 따라

#### 감점 1 — **Y2-5(중대)**: 앵커 ④의 "7자 일치"가 선언된 형태로 실행 불가능하다

앵커 ④는 라운드 20 Z2-5로 4자 → **7자**로 확장됐고, 추가된 3자 중 2자가 **그 직후 참조형으로 전환되며
재현 명령이 무효화**됐다. 재현:

```
# 7자 중 5자 — 성립
$ grep -cE "^\| T-NC-[0-9]+" E2-work-breakdown.md            → 20
$ grep -cE "^\| \**T-NC-" E3-parallel-schedule.md            → 20
   (E4 §A-3·§A-8 = 20건/100만, E5 §C 비-DoD 표 상단 = 20건 — 본문 대조로 일치)

# 6번째 — E1 §B 6번 요소
$ grep -v "舊" E1-agents-org.md | grep -oE "T-NC-01~[0-9]+"
T-NC-01~19      ← E1 §서두 "라운드20 수정 근거" 헤더가 舊 값을 인용(舊 문자 없음 → 필터 통과)
T-NC-01~20      ← §B 6번 요소 본문의 현행값

# 7번째 — E4 §B-4-1 배경 문단
$ grep -oE "T-NC-01~[0-9]+\(코드 외 [0-9]+건" E4-token-budget.md   → (출력 없음, 0건)
```

두 문제가 겹친다:

1. **E4 §B-4-1 배경 문단**은 라운드 20 Z2-3으로 `T-NC-01~19(코드 외 19건)` → `T-NC — E2 §E 그 시점 전수`로
   전환됐다(E4의 조치 자체는 재-stale 방지로 옳다). 그런데 앵커 ④가 부기한 **"참조형으로 전환되면 대상에서
   제외"라는 단서는 E1 §B 6번 요소 쪽 괄호에만** 있고 E4 §B-4-1 쪽에는 없다. 결과적으로 PMO가 앵커 ④를
   지시대로 실행하면 7번째 구성요소가 0건을 반환하는데 그것을 "위반"으로 볼지 "제외"로 볼지 규칙이 없다 —
   D9-1→D10-1→N-8이 세 차례 수리한 **"상시 위반 → 형해화"** 실패 모드의 재현 조건이다.
2. **E1 측 명령이 두 값을 반환**한다. `grep -v "舊"` 필터는 자기 정정 서술의 회고 인용을 배제하려는 것인데,
   E1 §서두의 라운드 20 수정 근거 행(`§B 6번 요소 "T-NC-01~19"→"E2 §E 그 시점 전수" 참조 전환`)은 舊 문자
   대신 **따옴표+화살표** 형식으로 옛 값을 인용하므로 필터를 통과한다. 상단 제외 단서를 적용해 E1을 대상에서
   빼면 해소되지만, 그 판단이 필요하다는 사실 자체가 "재현 명령만으로 판정"이라는 앵커 설계 원칙과 어긋난다.

요약하면 **앵커 ④는 현재 7자 중 5자만 살아 있고, 나머지 2자의 처리 규칙이 비대칭**이다. 앵커는 이 계획의
정합 유지 장치의 핵심이고, 그중 하나가 선언된 형태로 실행 불가능한 것은 영역 8의 직접 감점 사유다.

#### 감점 2 — **Y2-3 부수**: 대장의 "확인 방법(grep)"이 존재 확인에 그쳐 문안 괴리를 구조적으로 못 잡는다

PIVOT §6-11 #31(라운드 20 Z2-2 위임쌍)의 확인 방법은 `E1 grep "문서 산출물 태스크"`다 — E1에 그 라벨을 가진
행이 **존재하는지**만 본다. 그래서 E1 §C-2 9행이 E5 §B와 전혀 다른 문안을 담고 "문자 그대로 승격"이라 주장해도
대장 검증은 **수신 완료**로 통과한다. 앵커 ⑬도 N-8 정정으로 "존재 재현(1건 이상)만 판정"이라 같은 한계를 갖는다.

이 계획이 "확정 문안 인용·재해석 금지"를 매 라운드 결정 문서에 명시하는 만큼, **문안 일치 자체를 검증하는
장치**가 대장·앵커 어디에도 없다는 것은 구조적 공백이다(#28·#30의 확인 방법 `grep "compose config"`·
`grep "YAML 구문"`은 우연히 리터럴 조각이라 문안 검증 역할을 겸했으나, #31은 라벨만 쓴다).

#### 9.5 도달 수정 지시

1. **Y2-5**: 앵커 ④를 다음으로 재작성한다 —
