## D15-1. "구현 4건 웨이브" 파생 선언 동기화 + 앵커 ⑮ — H-1·H-12

**확정.** T-W2-18 편입(D14-1)으로 Wave 12가 4건이 되어 "구현 4건 웨이브"는 **6개(Wave 2·4·5·9·10·12)**,
E4 파생 지표는 **24 태스크-대기**다. 3문서(E3 §H·E4 §A-7·E5 §F 리스크1) 동시 정정 + E3 §H 완화책 적용
범위에 Wave 12 편입. **앵커 ⑮ 신설**(E5): "구현 4건 웨이브 집합 — E3 §C 실측(웨이브별 구현 태스크 수 추출)
= E3 §H 열거 = E4 §A-7 = E5 §F 3자 일치"(관계식만 — 14라운드 미검출의 구조 원인 봉합).

## D15-2. `live/[id].tsx` 준-공용 5종째 등재 — H-5

**확정.** `apps/subscriber/app/live/[id].tsx`는 3태스크(T-W1-03 Wave 8a·T-W2-11 Wave 10·T-W1-07a Wave 12)가
편집한다 — 웨이브가 전부 달라 **현 편성에 동시 편집은 없다**(재편 불요). D8-4 논거(다수 태스크의 반복 편집
단일점) 동형으로 **준-공용 5종째** 등재(동시성 1 — 향후 편성 변경 시 하드가드) + E3 §A 그래프에 T-W2-11의
해당 엣지 반영 + §I 체크 정합.

## D15-3. E1 검산 블록 형식 전환 — H-2 (3회차 재발 구조 종결)

**확정.** E1 §신규위임목록의 검산 블록에서 **줄번호 동반 출력 인용을 전면 금지**한다(`grep -n` 결과 붙여넣기
금지). 허용 형식: "문구 존재 확인(`grep -c "<문구>"` ≥ 1)" + 대상 절 명칭 서술. 앵커 ⑨의 해당 절 재검증도
같은 기준으로(존재 재현만). 재발 3회의 공통 원인이 "줄번호는 문서 진화로 반드시 드리프트한다"이므로 형식
자체에서 제거한다(자기 규칙 "줄번호 인용 금지"와 정합 복원).
