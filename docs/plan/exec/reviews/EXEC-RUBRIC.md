# 웹 피벗 실행계획 — 루브릭 평가 기준

> 독립 평가 에이전트는 이 기준으로만 평가한다. 1~10점, **0.1 단위**. 전 영역 **9.5 이상**이 통과선.
> 평가자는 내부 맥락·이전 평가를 무시하고, `docs/plan/exec/*`와 그 상위 정본(`docs/plan/*`)·리포 실체만 근거로 삼는다.

## 공통 점수 앵커

| 점수대 | 의미 |
|---|---|
| ~6.9 | 치명 결함(예: 병렬 충돌 필연·태스크 크기 산정 불가·토큰 폭주 무방비). 이 계획대로 실행하면 중단·재작업 확실 |
| 7.0~8.4 | 방향은 맞으나 주요 리스크에 완화책이 없거나 담당·발동 조건이 모호 |
| 8.5~9.4 | 실행 가능. 일부 배분 근거·검증 방법·복구 절차가 부족 |
| **9.5~10** | **치명 리스크 부재 + 모든 주요 리스크에 (완화책·담당·발동 트리거) 3요소 + 수치/근거 + 실행 체크리스트. 남은 것은 '실행'뿐** |

주의: 9.5는 "미래 보장"이 아니라 "실행계획 문서로서 더 고칠 것이 없는 상태"다. 불확실성 자체는 감점 사유가
아니며(실행 중에만 알 수 있는 것·실측 예정 명시 항목·트리거 대기), **방치**(식별·완화책·담당·트리거 없음)와
**근거 없는 배분·산정**이 감점 사유다. 앵커 충족 영역에 9.5를 주는 것은 관대함이 아니라 정확한 채점이다.

## 평가 영역 8개

| # | 영역 | 핵심 질문 | 주 근거 |
|---|---|---|---|
| 1 | 마스터플랜 정합성 | 태스크가 전부 승인된 계획(02 §E·08 W0~W4·각 문서 체크리스트)에서 파생됐고 신규 범위 발명이 없는가? 계획의 게이트·DoD·대장을 그대로 소비하는가? | EXEC-PLAN·E2 |
| 2 | 에이전트 편성 적정성 | 부하 에이전트(역할군)의 책임 경계·권한·위임 프롬프트 표준이 명확한가? 만든 자≠검증하는 자가 구조화됐는가? | E1 |
| 3 | 태스크 분해 적정성 | 태스크 크기 기준(1회 실행 완결·검증 가능 단위)이 명시·일관 적용됐고, 각 태스크에 산출물·DoD·파일 소유권이 붙어 있는가? | E2 |
| 4 | 병렬 안전성 | 의존 그래프·파일 소유권 배타·공용 계약(shared 등) 변경의 단독 슬롯 규칙으로 병렬 충돌이 구조적으로 방지되는가? | E3 |
| 5 | 토큰·연속성 관리 | 동시 실행 상한·라운드/태스크당 토큰 예상·세션 한도 중단 시 재개 프로토콜이 실증 근거와 함께 있는가? | E4 |
| 6 | 모델·에포트 배분 | 작업 성격별 모델(sonnet/opus 등)·에포트 배분에 근거가 있고 과소/과대 배분 리스크가 관리되는가? | E4 |
| 7 | 품질 게이트 | 태스크 완료 판정(테스트·qa-verifier·DoD 실측 재현)·회귀 방지·PR 흐름이 글로벌 헌법(Trust but Verify)과 정합한가? | E5 |
| 8 | 추적·정합 유지 | 실행 중 문서–코드–대장의 정합을 유지하는 장치(발주–수신 대장 연장·SSOT 갱신 규칙·진행 보고 주기)가 있는가? | E5·EXEC-PLAN |

## 평가 절차 (평가자 지침)

1. `docs/plan/exec/EXEC-PLAN.md`부터 E1~E5 전 문서를 정독하고, 상위 정본(`docs/plan/PIVOT-PLAN.md`·02 §E·08 §A·§E)과 대조한다.
2. 영역별 감점 사유를 문서명·섹션 인용으로 지목한다("막연히 부족" 금지). 태스크 표는 표본이 아니라 **전건**을 상위 체크리스트와 대사한다.
3. 각 영역: 점수(0.1) + 감점 사유 + 9.5 도달 수정 지시(실행 가능한 문장).
4. 결과를 `docs/plan/exec/reviews/EXEC-EVAL-ROUND-<n>.md`에 기록: 총평 → 점수표 → 영역별 상세 → 정합성 이슈 목록.
5. 이전 라운드 평가문서(`EXEC-EVAL-ROUND-*`)는 읽지 않는다(독립성).
