> [EXEC-EVAL-ROUND-4](EXEC-EVAL-ROUND-4.md)의 이슈 16건(V-1~V-16) 중 선확정 필요 6건(V-1·3·4·5·7·14)과

## D4-1. E5 §C PoC 행의 폐기 문안 교체 — V-1

**확정.** E5 §C "W1 선행 PoC" 행의 "미완료 시 W1 착수 차단"은 **EXEC-DECISIONS #2로 폐기된 문안**이다.
#2 확정 해석("기자 촬영·업로드 트랙(T-W2-02 이후 = Wave 5) 착수 전 완료 — W1 구독자 웹(시청 전용)은
비차단")으로 교체하고 #2를 인용 병기한다. 조율자는 **EXEC-DECISIONS #2의 영향 문서 목록에 E5 §C를 추가**한다
(K-10 "인용처 전건 등재" 복구).

## D4-2. 라우트 스모크 DoD의 모수 규칙 — V-3 (EXEC-DECISIONS #4로 기록)

**확정.** 02 §E-9 ③의 "화면 라우트 22개"는 **피벗 시점 실측 스냅숏**이며, W2 판정의 모수는
"**판정 시점의 화면 라우트 전수**"다(재현 명령 고정: `find apps/{reporter,control-center,subscriber}/app
-iname '*.tsx' ! -path '*__tests__*'`에서 `_layout.tsx`류 제외). 본 계획 신설 3라우트(T-W1-09 문의하기·
T-W1-10 편성표·T-W2-09 주민 링크)를 포함하면 판정 시점 예상 모수는 **25**다. 통과 기준은 모수 무관 **전건
(100%)** 유지 — 라우트 신설·삭제 시 모수는 자동 갱신되며 "22개" 고정 수치를 판정에 쓰지 않는다.
조율자가 **EXEC-DECISIONS #4**로 기록(02 정본 재정의 아님 — 스냅숏 수치의 판정 시점 해석). 적용:
E2 T-W2-07·T-NC-07, E5 §C W2 행 + §D 앵커(모수 재현 명령).

## D4-3. W3 선행조건 오인용 정정 — V-4 (기록 불요 — 정본 준수 방향)

**확정: 정본 그대로 따른다**(완화 유지가 아니라 오인용 정정이므로 EXEC-DECISIONS 불요).
E3 §C Wave 16 선행 열·§D를 "**W1 종료(Wave 12) + T-NC-08(스토어 계정 개설) 완료**"로 정정한다(08 §A W3
선행조건 원문). 단 T-NC-08은 사용자 의존 외부 리드타임이므로, **코드 선행 준비는 §F G9 우회와 동형**으로
"로컬 검증 범위 내 선행 가능(스토어 제출 행위(T-NC-10)만 하드 차단)"임을 같은 셀에 부기한다 — 이 부기는
08 §D 승인 지연 완화책 준용이라 정본과 상충하지 않는다. E2 §C W3 선행 문단과 문안 일치 확인.

## D4-4. 패널 R1 게이트 기점 정정 — V-5 (기록 불요 — 정본 준수 방향)

**확정.** 패널 R1(T-NC-04)의 개방 기점 = "**T-W1-01 + T-W1-02 완료(= `packages/ui` 토큰 게이트 완료,
Wave 5) 직후 ~ T-W1-03 웹 export 스모크 사이**"다. 근거: 02 §E-1 "스키마 반영만으로는 이 게이트가 닫히지
않는다" + 08 §A 시간축 매핑 U3("토큰 게이트 완료 → 패널 R1 순서 확정"). 舊 "T-W1-01(Wave 3)만으로 개방"은
오인용. 적용: E2 §E T-NC-04·E3 §D·E5 §C W1 패널 R1 행(3문서 동일 문안).

## D4-5. W3 내부 순서 준수 — V-7 (기록 불요 — 정본 준수 방향)

**확정.** 02 §E-10의 순서 선언(manifest/SW → TWA → iOS 쉘)을 의존 엣지로 반영한다:
**T-W3-02(manifest/SW) → T-W3-03(TWA)·T-W3-04(iOS 쉘)**(TWA는 PWA manifest의 직접 소비자 — 실질 기술

A팀 — 라운드 2·3 규칙 유지).

**확정.** PIVOT §6-11 #9 상태 칸의 수치 인용을 라운드 3 실산(합계 1,618만·최대 Wave 5=166만 ≤ 200만)으로
