# EXEC-ROUND-27-DECISIONS — 라운드 27 수정 선확정 (조율자)

> 입력: [EXEC-EVAL-ROUND-27.md](EXEC-EVAL-ROUND-27.md) 이슈 H2-1~H2-4(중 1·경 2·권고 1·치명 0), 실산 평균 **9.575**(舊 9.5625), 9.5 미만 **2영역**(5·8).
> **앵커 ①~⑯ 전종 성립**·E4 산술·lockfile D6-1 위반 0·대장 54행/121행 실측 확인됐다.
> 모수 변동 없음 → **3팀 병렬**. 조율자 직접 수행분이 이번 라운드에 가장 크다(H2-1 본체·H2-2 일부).

## D27-0 (H2-1, 조율자 자기 귀책) — **진짜 미등재가 두 스윕을 생존했다**

**결함**: `E3 §신규 위임 #5`(E5 §B 의존성 행 6종→8종 갱신 요청 — 라운드 25 제출분)의 상태 칸이 **`미등재 — 조율자 스윕 등재 요청`**인데, §6-11에 대응 행이 **실제로 없다**(조율자 실측: 발주처가 E3인 행은 #9·#10·#38뿐, `E3 §신규 위임 #5` 발주 행 **0건**). 즉 **진짜 미등재**가 라운드 25·26 두 스윕을 통과했다.

**왜 검출되지 않았나(구조적 원인)**: D7이 상태 칸 형식을 **두 가지**(`→ 6-11 #n 참조` / `등재 필요(6-11 편입 대기)`)로 규정했는데, 이 행은 **어느 쪽도 아닌 제3의 문구**(`미등재 — 조율자 스윕 등재 요청`)를 쓴다. 그래서 ① PMO 미등재 탐지 grep이 히트 0 ② 앵커 ⑫ 번호 정합 대조가 후보를 형성하지 못한다. **"분모 밖 위임" 7회차**이며, 이번에는 위임 자체가 아니라 **상태 칸 문구의 형식 이탈**이 분모를 비운 형태다.
※ 실은 조율자도 라운드 25·26 스윕에서 이 문구를 전환 대상 grep 패턴에 넣어 썼는데(`미등재 — 조율자` 포함), 그때 잡힌 것은 E4·E5 행이었고 E3 #5는 **그 라운드의 신규 제출분이 아니라 이전 라운드 잔여**라 스윕 대상 목록에 오르지 않았다. **"그 라운드 제출분만 등재"라는 암묵 전제가 잔여를 영구히 놓치는 경로**였다.

**조치**:
- **조율자**: §6-11에 E3 §신규 위임 #5를 **정식 등재**하고 같은 스윕에서 E3 상태 칸을 `→ 6-11 #n 참조`로 전환한다. **아울러 전 문서에서 D7 두 형식 밖 상태 칸을 전수 스캔**해 잔여를 일소한다(E5 §신규 위임 #23도 형식 밖 — 평가자 지적).
- **C팀(D27-1)**: 형식 배타 규정 + 앵커 ⑫ in-place 확장으로 재발을 구조적으로 막는다.

## D27-1 (H2-1 후단, 중) — **C팀**: 상태 칸 형식 배타 규정 + 앵커 ⑫ 확장

1. **형식 배타 규정**: §D(또는 상태 SSOT 규정 절)에 "신규 위임 목록 상태 칸은 **`→ 6-11 #n 참조` 또는 `등재 필요(6-11 편입 대기)` 두 형식만** 허용한다. 그 외 문구(예: `미등재 — 조율자 스윕 등재 요청`)는 **형식 위반 1건**으로 보고하며, PMO 탐지·앵커 ⑫의 분모를 비우는 경로이므로 값의 정오와 무관하게 위반이다"를 명문화하라.
2. **앵커 ⑫ in-place 확장**: 현행 ⑫는 `→ 6-11 #n 참조`를 가진 행만 대조한다 → **"두 허용 형식 어디에도 속하지 않는 상태 칸"을 별도 후보로 검출**하는 축을 추가하라. 재현 명령을 동반하고 값은 박제하지 마라.
3. **스윕 전제 정정**: 조율자 스윕이 "그 라운드 제출분만" 처리하던 암묵 전제가 잔여를 영구히 놓치는 경로였다 → **"스윕은 그 시점 전 문서의 미전환·미등재 전수를 대상으로 한다"**를 §D 절차에 1구 명시하라(D23-6 양단 동기 규칙의 보완).

## D27-2 (H2-2, 경) — **C팀 + 조율자**

D26-4가 "존량 잔여 0 종결"이라 판정했으나 탐지 glob이 **`docs/plan/exec/E[1-5]-*.md`**라 exec 8문서 중 **`EXEC-PLAN.md`(2곳)·`EXEC-DECISIONS.md`(1곳)가 정의역 밖**이었다. 셋 다 리포 루트에서 `No such file or directory`가 난다. 그중 **`EXEC-PLAN.md:39`는 앵커 ⑥ 개시 라벨 대조의 우항 소재 자체**라 앵커가 자기 대조 대상을 재현 불가 상태로 두고 있었다.
- **C팀**: 앵커 ⑨ cwd 판정 항목과 D26-4 탐지 명령의 **glob을 exec 전 문서로 확장**(`docs/plan/exec/*.md` 또는 동등). 확장 후 실행해 히트를 보고하라.
- **조율자**: `EXEC-PLAN.md`·`EXEC-DECISIONS.md`의 해당 3곳을 리포 루트 기준 전체 경로로 통일한다(두 파일은 조율자 소유).

## D27-3 (H2-3, 경) — **A팀**

D26-1이 "값 제거로 위상 불일치는 원리적으로 불가능"이라 했는데, **E4 §A-8 ④가 새로 넣은 단정문**("라운드26은 R에 포함되지 않는다")이 부착 명령 출력과 저촉한다 — 조율자 실측 **R = 26**(라운드 26 수정 커밋 `95a8682` 실재). 값을 지우면서 **값 대신 단정을 넣은 것**이 원인이다.
- **A팀**: 해당 단정문을 **시점 명시형**으로 교체하라 — "R은 그 시점 명령 출력이며, 본 절 작성 시점의 수정 커밋이 아직 기록되지 않았다면 그 라운드는 R에 포함되지 않는다"처럼 **특정 라운드 번호를 못 박지 않는 형태**로. 교체 후 부착 명령을 실행해 단정과 출력이 저촉하지 않음을 실증하라.
- **일반화**: 값 박제 제거의 취지는 "라운드가 진행되면 움직이는 것을 문서에 고정하지 않는다"이며, **특정 라운드를 지목하는 단정문도 같은 범주**다. 자기 파일에 동형이 더 있는지 점검하라.

## D27-4 (H2-4, 권고) — **C팀 + B팀**

앵커 ⑯의 재현이 **행 단위**라 **줄바꿈으로 쪼개진** 전수 주장을 구조적으로 놓친다(실례: E2 §0 144–145행의 "무기록 항목 0건"이 두 행에 걸쳐 있어 미검출).
- **C팀**: 앵커 ⑯ 재현을 **줄바꿈 정규화 후 문장 단위**로 판정하도록 정의를 보강하라(단락을 합친 뒤 문장 분리, 또는 다중 행 컨텍스트 grep). 정의 변경 후 **오탐이 늘지 않는지 대조군으로 실증**하라 — 라운드 25에 네가 마커 검사에서 쓴 방식(마스킹 유/무 대조)과 동형.
- **B팀**: C팀 정의로 재탐지된 자기 파일 존량 중 지목분(E2 §0 144–145행)을 처리하라(ⓐ 재현 부착 / ⓑ 회고 강등 / ⓒ 삭제 중 택일 — 앵커 ⑯ 존량 규칙).
