공동 배정 금지")이 명문화돼 있고, 실제로 T-W2-16이 이 원칙에 걸려 16a/16b로 분할된 이력이 §A-1에 기록돼 있다.

### 영역 6. 모델·에포트 배분 — **9.6**

**모델 축(§B-1·§B-2·§B-3)**: 작업 "성격"별 배분(구현·문서·PMO·QA 조율 = sonnet 기본 / 설계 판단·독립 평가·
리뷰 = opus / 조율자 본체 = 배분표 대상 아님)에 근거가 붙어 있고, **DDD6 초기 opus 선배정 5건**
(T-W0-01·T-W1-05·T-W2-08·T-W3-03·T-W3-04)이 "높음 4조건 a~d 각각의 리포 최초 1건"이라는 **선정 규칙**에서
도출된다 — 임의 배분이 아니다. 전환 규칙이 상향 3조·하향 2조 + **부정 분기**("DDD6 최초 태스크가 FAIL이면
후속도 opus 유지")까지 갖췄고, sonnet 적합성 판정 시점을 **Wave 2 종료 보고**로 못 박고 기준을
"게이트② FAIL율 ≥25%, 분모 = 해당 웨이브 sonnet 구현 태스크 수"로 수치화했다.

**과대 배분 감지(§B-3)**는 특히 드문 설계다 — 과소 배분만 잡는 계획이 흔한데, 여기는 **표본 정의**(웨이브당
opus 1건 무작위)와 **임계값**(정보 밀도/토큰이 직전 opus 표본 3건 중앙값의 1/2 미만)을 함께 두고,
"opus 표본 3건 미만이면 유보가 정상 상태", "노출액 상한 175만"까지 규정한다. "신규 판단 요소"의 계수 규칙도
완료 보고 검토 요약 절의 항목 수로 조작적 정의돼 있다.

**에포트 축(§B-4)**: 3등급(낮음/높음/최고)을 정의하고 **"크기 ≠ 에포트"** 원칙을 명시한다(T-W2-05·06은 XL이지만
기계적 반복이라 낮음). 등급 판정이 4조건 (a)~(d)로 기계화돼 있고, **적용 수단**(D10-2)이 "위임 프롬프트의
추론 지시어"로 구체화돼 있어 등급이 실행 가능한 조작으로 내려온다.

**전건 분류 실측(평가자 직접 계수)**: §B-4 분류표(2쌍 열 구조)의 양쪽 열 태스크 ID를 추출하면 **46건 고유**로
E2 코드 46건과 차집합 0. 집계도 재계수 일치 — 높음 10 + 낮음 36 = **46**, opus 5 + sonnet 38 + 조율자 본체 3 = **46**.
§B-4-1이 코드 외(T-TRIG 3·T-NC 20)·비구현 역할(PMO/QA 리드/법무)·qa-verifier의 에포트까지 덮어 **분모 밖이 없다**.

**감점 없음.** 9.5 앵커를 넘어 **9.6**을 주는 근거: 루브릭이 요구하는 "근거 + 과소/과대 배분 리스크 관리" 중
**과대 배분 축까지 표본·임계값·유보 조건·상한을 갖춘 것**은 앵커 요구를 상회하며, 46건 전건 분류가
평가자 재계수로 검증된다(자기 매칭 없음 — 계수 입력이 타 문서 E2의 ID 집합이다).

### 영역 7. 품질 게이트 — **9.5**

**4단 게이트(§A)**: ①구현 에이전트 자가 검증 → ②qa-verifier 독립 검증 → ③회귀 → ④조율자 승인 후 PR.
순서 강제("임의의 게이트를 건너뛴 '완료' 선언은 무효 — 발견 즉시 게이트①로 반려")와 게이트별
주체·입력·실행·증적·통과 기준·실패 시 조치 7열이 전건 채워져 있다. 글로벌 헌법의 Trust but Verify가
*"로그 없는 '완료' 문구는 그 자체로 게이트① 미통과"*로 조작화된다.

**정직한 예외 처리**: 테스트 스위트가 없는 4개 태스크군(인프라 `infra/*` 6건 · 쉘 골격 `infra/shell/**` 2건 ·
CI 설정 `.github/workflows/*` 4건 · 문서 산출물 2건)에 대해 게이트①의 "테스트 존재" 요건을 **정적 검증 명령**으로
대체하고, 각 군의 명령을 §B에 구체적으로 적는다(`docker compose … config -q`·`nginx -t` / `python3 -m json.tool`·
`plutil -lint` / `yaml.safe_load` / DoD 항목별 자가 대조 + 링크 실재 grep). **공허한 그린 금지**를 명문화한
쉘 골격 행("compose·nginx 축은 적용 대상 없음 — 실행하지 않는다")은 특히 정확하다. 4군 전부 "닫힌 목록 아님"
조항을 달고, 각 군의 게이트①/② 축이 E1 §C-2 필수 삽입문으로 결박된다.

**회귀 방지(§B·게이트③)**: 공용 자산 **5종** 변경 시 루트 전체 회귀 강제, 의존성 추가 태스크는
`pnpm install --frozen-lockfile` + 루트 전체 회귀, before→after 건수 비교, **제거형 산출물의 테스트 감소 예외**
(감소 ID 1건씩 명시 시 통과, 무설명 감소는 회귀), **델타 귀속 규칙(D10-4)**(동일 웨이브·동일 워크스페이스
2건 이상이면 머지 순차화, 앞 태스크의 after가 뒤 태스크의 before) — 병렬 구현을 유지하면서 회귀 귀속을
태스크 단위로 분리하는 설계가 정교하다. 리포 실측 기반의 정직 정정(D13-1: "루트 lint의 실효 범위는
`@gachinol/api`·`@gachinol/media-worker` 2곳뿐 — 앱의 게이트①·③ 축은 test+typecheck")도 확인했다.

**post-merge 경로**: 자기머지 환경에서 게이트④ 통과 즉시 main에 반영되므로 "머지 보류"가 불가능한 공백을
D16-1이 4단계(귀속 식별 → hotfix/revert → **핫픽스도 4단 게이트 전 구간 통과** → EXEC-DECISIONS 기록)로 닫는다.

**실집행 수단의 정직성(D15-4)**: "required = 머지 차단"이 존재하지 않는 기계적 강제를 전제한다는 점을 인정하고,
브랜치 보호 부재 환경에서 실집행은 **조율자의 병합 절차 통제**뿐임을 명시한다. required 목록의 정본을
E2 T-W1-11b 산출물 열 한 곳에 두고 E5는 인용만 하는 구조(D22-2)도 정본 이중화를 막는다.

**W단계 DoD(§C)**: 9행 전건에 DoD 항목(정본 인용) · 실측 명령/절차 · 증적 형식 · 저장 위치 · 실행 담당 · 판정
승인 6열이 채워져 있고, **실측 실행(QA 리드) ≠ 판정 승인(조율자)** 분리가 G6의 DoD 확장으로 규정된다.
"실행자=승인자 동일 주체 예외"는 2건(W1 ③ · T-NC-02)으로 **전수 열거**되고 공통 근거(결정·접수 행위라 D5 적용
대상 아님)와 재현 명령이 부착돼 있다 — 평가자 재실행 결과 히트 3건 중 정의·앵커 인용 1건을 제외한
**정확히 2건**으로 열거와 일치.

**감점 없음.**
