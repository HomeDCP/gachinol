## A. 태스크 완료 판정 — 4단 게이트 (G6)

**원칙**: "테스트 미실행 완료 선언 금지"(글로벌 CLAUDE.md Trust but Verify). 4개 게이트는 **순서대로만** 통과
가능하며, 임의의 게이트를 건너뛴 "완료" 선언은 무효 — 발견 즉시 게이트 ①로 반려한다.

| 게이트 | 주체 | 입력 | 실행 내용 | 산출물/증적 | 통과 기준 | 실패 시 |
|---|---|---|---|---|---|---|
| **① 구현 에이전트 자가 검증** | 태스크를 구현한 서브에이전트 본인 | 태스크 AC(E2 정의) | 태스크가 건드린 워크스페이스 한정 테스트·타입체크 실행(§B 명령 표 참조). E2E 관련 태스크는 해당 스위트 지정 실행 | **실행 로그(명령 전문 + 결과 요약, 그린/레드·건수)를 완료 선언 문구에 동봉** — 로그 없는 "완료" 문구는 그 자체로 게이트 ① 미통과 | AC 전항목에 대응하는 테스트 존재 + 전부 그린 | 레드 또는 로그 누락 시 태스크는 **미완료 상태 유지**, PR 생성 금지(다음 게이트로 진행 불가) |
| **② qa-verifier 독립 검증** | **qa-verifier**(구현 에이전트와 별도 기동, 컨텍스트 격리 — "만든 자 ≠ 검증하는 자") | 태스크 AC + 변경 diff + 게이트①의 로그(참고용, **신뢰하지 않고 최소 1개 AC는 반드시 독자 재실행/재현**) | AC 항목별 재현: 직접 Bash 실행·Grep·Read로 실측(자가검증 로그를 그대로 베끼지 않는다 — PIVOT-PLAN Q1 원칙 "확인=실행한 결과만"을 동형 적용). **코드는 수정하지 않는다**(qa-verifier 정의) | PASS/FAIL 판정 + 근거(실행한 명령·grep 결과) — PR 본문 "QA 검증" 절에 인용 | AC 전항목 PASS | FAIL 시 게이트 ①로 반려(구현 에이전트 재기동 또는 재위임), qa-verifier는 임의로 고치지 않는다 |
| **③ 회귀** | 조율자 또는 QA 리드 | 영향받는 워크스페이스 목록(E2 소유권 명시분 + 의존 그래프상 하류) | §B 명령 표에 따라 개별/전체 test·typecheck 실행. 공용 자산(`packages/shared`·Prisma 스키마·CI 설정·`packages/ui`) 변경 태스크는 **루트 전체**(`pnpm test`·`pnpm typecheck`, turbo 전파) 강제 | 테스트 건수 **before→after** 비교(CLAUDE.md §11 로드맵 관례 계승, 예: "api 유닛 294→381·e2e 41→52") | 회귀 0 — 기존 테스트 건수 감소·레드 없이 신규 건수만 증가(또는 불변) | 회귀 발견 시 게이트 ①로 반려, PR 생성 보류 |
| **④ 조율자 승인 후 PR** | 조율자(PM) | ①~③ 통과 증적 전건 | ①~③ 증적 확인 + G3 파일 소유권 위반(병렬 충돌) 없음 확인 + G7 신규 위임 등재 여부 확인(§D) | 전건 충족 시 PR 생성 지시 | ①~③ 중 하나라도 증적 부재/부실 발견 시 **PR 생성 즉시 중단**, 회귀 게이트로 롤백 |

**"테스트 미실행 완료 선언 금지" 위반 시 조치** (어느 게이트에서 적발되든 동일 절차):

1. 적발 즉시 해당 태스크를 **미완료로 원복**(PR이 이미 생성됐다면 머지 보류·draft 전환).
2. 위반 사실을 `EXEC-DECISIONS.md`(§D 참조)에 1건으로 기록 — 재발 방지가 목적이지 문책이 목적이 아니므로 "무엇이
   누락됐는지"(로그 자체 부재 / 로그는 있으나 레드 상태로 강행 / AC 미스매치)를 구분해 기록한다.
3. 동일 에이전트 재기동 또는 태스크 재위임(위임 프롬프트에 "게이트① 로그 첨부 의무"를 굵게 재명시 — E1 위임
   프롬프트 표준에 반영 요청, 아래 완료 보고 참조).
4. **동일 유형 위반이 한 웨이브 내 2회 이상 반복**되면 E1의 위임 프롬프트 표준 자체를 조율자가 재점검(발동
   트리거 수치화 — §F 리스크 표 참조).

## C. W 단계 DoD 판정 절차

**원칙**: DoD 항목·목표 수치의 정본은 [08-rollout-transition.md](../08-rollout-transition.md) §A·[02-web-architecture.md](../02-web-architecture.md) §C다 — 본 절은 그 수치를 **재정의하지 않고**, "누가 어떤 명령으로
실측하고 어떤 형식의 증적을 어디에 남기는가"만 정한다(08이 08 §A에서 이미 위임한 것과 동일 원칙 — "08은 인용만
한다"). 판정에도 PIVOT-PLAN Q1 원칙을 그대로 적용한다: **"판정했다"는 실제로 실행한 스크립트·캡처가 있을 때만
기재**하며, 실행 없이 "확인됨"이라 쓰는 것은 그 자체로 §A 위반과 동일하게 취급한다.

**역할 분리**(G6 원칙의 DoD 확장): 실측 **실행**은 QA 리드(또는 지정 서브에이전트)가 수행하고, 실측을 만든
FE/BE 리드가 스스로 자기 구현의 DoD 충족을 선언하지 않는다. 최종 판정 **승인**은 조율자(PM)가 한다.

## D. 대장·정합 연장 운영 (G7)

**연장 운영 대상**(PIVOT-PLAN §6 소유, 실행 중에도 동일 규칙·동일 문서에 계속 누적 — 새 별도 대장을 만들지
않는다, 단일 원천 유지):

- §6-1~6-10의 **발주–수신 대장**(67행) 및 그 등재 규칙
- §6-5 **SSOT 인용 대조**(값·정의·기산점 변경 시 인용처 전건 재검증)
- **등재 책임 규칙**(라운드15): 새 위임을 만든 문서(태스크) 소유자가 완료 보고에 "대장 등재 필요 신규 위임
  목록"을 명시 제출 — 실행 단계에서도 동일하게, **태스크 완료 보고 = 게이트①의 완료 선언**에 이 목록을 포함
  시킨다(없으면 "없음"이라고 명시해야 하며, 무언급은 그 자체로 §A "테스트 미실행 완료 선언 금지"와 동급의
  절차 위반으로 취급).
- **Q1 원칙**(라운드8): "확인"·"수신 완료"는 **그 시점에 실제로 실행한 grep 결과**가 있을 때만 기재.

**실행 중 신규 위임/괴리 발생 시 처리 절차**:

1. **웨이브 종료 시 PMO 기동**(정기): E3가 정의하는 웨이브 하나가 끝날 때마다 조율자가 **PMO 서브에이전트**를
   1회 기동한다. PMO는 그 웨이브에서 완료된 태스크들의 완료 보고(§A 게이트① 목록)를 취합해 "대장 등재 필요
   신규 위임"이 실제로 대장에 반영됐는지 **직접 grep 재현**한다(발굴이 아니라 **검증** — 등재 책임은 태스크
   소유자에게 있고 PMO는 이중 확인만 한다, PIVOT-PLAN 라운드8 G-8 "분모 밖 위임" 재발 방지 구조를 실행
   단계에 그대로 이식).
2. **코드가 계획과 달라지는 결정 발생 시**(정기 외 수시 — 예: 태스크 실행 중 기술적 이유로 08·02 등이 정한
   설계와 다른 접근을 택함): 해당 결정을 즉시 `docs/plan/exec/EXEC-DECISIONS.md`(EXEC-PLAN G7이 이미 지정한
   횡단 결정 문서 — 라운드 번호 대신 발생 순번 "EXEC-DECISIONS #n"으로 누적)에 기록한다. 기록 항목: 결정
   배경, 원 계획 문서·절 인용, 실제 채택안, 영향받는 문서 목록.
3. **계획 문서 갱신**: EXEC-DECISIONS 기록과 동시에(같은 태스크 완료 이전) 조율자가 영향받는 계획 문서
   (01~08 또는 E1~E5)의 해당 절을 직접 갱신하고 **갱신 사실을 grep으로 재검증**한다(라운드18까지 반복
   확립된 "조율자 직접 반영·grep 검증" 패턴 그대로).
4. **대장 편입**: 위 신규 위임쌍은 PIVOT-PLAN §6에 새 소절을 추가하는 방식으로 편입한다(제안: 실행 단계 전용
   "6-11. EXEC 웨이브 신규 위임" 소절 신설 — 6-6~6-10과 동일 표 형식: 발주처|수신처|확인 방법(grep)|기한|
   상태|미수신 시 조치). 이 편입은 **조율자**가 §6 소유자로서 직접 수행하며, 새 대장을 만들지 않는다.
5. **미등재 발견 시 조치**: PMO grep 재현에서 등재 누락이 발견되면 그 웨이브 안에서 즉시 반영·재검증하고
   마감한다(라운드9 "적발된 1건은 조율자가 즉시 반영·재검증해 같은 라운드 안에 마감" 패턴 계승) — 다음
   웨이브로 이월 금지.

## E. 진행 보고 (웨이브 종료 시)

```
6. 다음 웨이브: E3 의존 그래프 기준 진입 가능 태스크 목록
```

  운영하며, EXEC-PLAN G7이 이미 지정한 `EXEC-DECISIONS` 문서명을 그대로 사용.
- **G8**: §B(회귀)·실행 체크리스트의 PR 단위 항목이 G8의 브랜치→PR→자기머지→정리 흐름과 확립된 로컬
  `--no-ff` 워크플로를 그대로 인용(재정의 없음).
- **범위 준수**: 태스크 목록·DoD 원 수치(E2·02·04·08)·웨이브 정의(E3)·모델 배분(E4)은 어디서도 재정의하지
