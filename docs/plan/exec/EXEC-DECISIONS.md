## EXEC-DECISIONS #1 — 인증 어댑터 공용 패키지 추출 없이 기자·관제 독립 구현 (2026-08-04)

- **배경**: [08-rollout-transition.md](../08-rollout-transition.md) §A "병렬성" 문단은 "W2 내부에서 기자·관제도
  병렬 가능(인증 어댑터를 공용 패키지로 먼저 추출)"이라 적었으나, E2 태스크 분해에는 공용 패키지 추출 태스크가
  없다([E3](E3-parallel-schedule.md) §H 리스크 표가 적발·판단, 완료 보고로 조율자에 기록 위임).
- **원 계획 인용**: 08 §A 병렬성 문단(W1·W2 독립 + 괄호 단서).
- **채택안**: 08 원문의 괄호 단서는 병렬화를 가능케 하는 **선택적 최적화 아이디어**이지 필수 선행조건이 아니다.
  본 실행계획은 공용 패키지 추출 없이 T-W2-01(기자 auth 웹 어댑터)·T-W2-04(관제 auth 웹 어댑터)를 **각자 독립
  구현**으로 진행한다. 근거: ① 공용 패키지化는 G3 단독 슬롯을 강제해 오히려 병렬성을 해침, ② 두 앱의 auth
  패턴은 reporter→control-center 동형 이식으로 이미 검증돼 있어 독립 구현이 더 단순·안전, ③ 파일 소유권이
  `apps/reporter/src/auth/*` vs `apps/control-center/src/auth/*`로 배타적이라 병렬 배치에 지장 없음(E3 웨이브
  편성 참조).
- **영향 문서**: 08 무변경(마스터플랜 자체를 바꾸지 않는 실행계획 단계 해석 확정). E2 T-W2-01/T-W2-04·E3 해당
  웨이브 편성이 이 해석을 이미 반영. 대장 등재는 PIVOT-PLAN §6-11.

## EXEC-DECISIONS #2 — PoC 게이트의 차단 범위 축소 해석 (2026-08-04, EXEC-EVAL-ROUND-1 X-6 · EXEC-ROUND-1-DECISIONS D2)

- **배경**: [08-rollout-transition.md](../08-rollout-transition.md) §A는 W1 선행조건에 "`<input capture>` 대용량
  업로드 실기기 PoC 완료"를 두고 §E 3-1은 "미완료 시 W1 착수 차단"이라 적었다. 그러나 E3 초안은 이를 근거 기록
  없이 Wave 9(기자 웹 전환 후반)까지 이연해 문서 내부 모순(§A 그래프는 T-W2-02 포함, §D 배치는 Wave 9만)이
  생겼다 — EXEC-EVAL-ROUND-1이 "기준 불균일"(가벼운 건은 #1로 기록, 무거운 게이트는 무기록 완화)로 적발.
- **원 계획 인용**: 08 §A W1 선행조건·08 §E 3-1("기한: W1 착수 전") ↔ 02 §E 0-1("**W0~W1 병행** PoC",
  "§E 7번(기자 앱 웹 전환)의 착수 여부를 좌우", 실패 시 07 §1-3 대안 발동 + "미착수 상태로 §E 7번 진행 금지").
- **채택안**: 차단 범위를 "**기자 촬영·업로드 트랙(02 §E 7번 계열 = T-W2-02 이후) 착수 전 완료**"로 좁혀
  해석한다. 근거: ① 02 §E 0-1 자신이 실질 하류를 §E 7번으로 명시, ② 정본 명명 자체가 "W0~W1 **병행** PoC"라
  W1 전체 선행과 문언 내 긴장이 있음, ③ PoC가 검증하는 것은 업로드 경로이므로 W1 구독자 웹(시청 전용)은
  실패 영향권 밖. 실행계획 반영: T-NC-03은 "**Wave 5(T-W2-02) 착수 전 필수 완료**"로 배치(E3 §D), 하류 영향은
  Wave 5의 T-W2-02 + Wave 9의 T-W2-03.
- **영향 문서**: 08·02 무변경(해석 확정). E3 §A·§C·§D, E2 §C W1 선행 문단(본 결정 인용 병기),
  **E5 §C "W1 선행 PoC" 행**(라운드 4 추가 — EXEC-EVAL-ROUND-4 V-1이 본 목록의 E5 §C 누락으로 폐기 문안
  "미완료 시 W1 착수 차단"이 E5에 잔존함을 적발, D4-1로 편입·교체). 대장 등재는 PIVOT-PLAN §6-11.

## EXEC-DECISIONS #3 — 웨이브 토큰 상한 145만 → 200만 상향 (2026-08-04, EXEC-EVAL-ROUND-1 X-12 · E4 §G 라운드 1 제출분)

- **배경**: 舊 상한 145만은 **qa-verifier(게이트②) 비용을 전혀 계상하지 않은 합계** 위에서 산정된 값이었다
  (EXEC-EVAL-ROUND-1 영역 5 감점 1 — "판정 불성립" 적발). E4가 라운드 1 수정에서 +qa-verifier 열·XL 버킷을
  반영해 17웨이브 전건을 재계산한 결과(합계 1,770만, 최대부하 Wave 5 = 재편성 전 228만 / D3 재편성(구현 ≤4 +
  qa-verifier 슬롯 1 예약) 후 ≈196만), 145만은 유지 불가로 판정됐다.
- **원 계획 인용**: E4 §A-3(舊 "웨이브 상한 145만")·§A-4("근거 기록 없이 상한 상향 금지").
- **채택안**: **웨이브 상한 = 200만 토큰**(재편성 시나리오 최대 196만에 소폭 여유). 145만은 폐기. §A-4의
  초과 조치(사전·진행 중·사후)는 새 상한 기준으로 동일 적용. 이 기록이 §A-4가 요구하는 "근거 기록"이다.
- **영향 문서**: E4 §A-3·§A-4·§A-6(재계산 완료), E3 §C(웨이브 편성의 예산 검산 기준). 대장 등재는 PIVOT-PLAN §6-11.

## EXEC-DECISIONS #4 — 라우트 스모크 DoD의 모수 = 판정 시점 전수 (2026-08-04, EXEC-EVAL-ROUND-4 V-3 · EXEC-ROUND-4-DECISIONS D4-2)

- **원 계획 인용**: 02 §E-9 ③(재현 명령 포함)·08 §A W2 DoD "라우트 22개 스모크".

  PIVOT-PLAN §6-11.
