## EXEC-DECISIONS #1 — 인증 어댑터 공용 패키지 추출 없이 기자·관제 독립 구현 (2026-08-04)

  병렬 가능(인증 어댑터를 공용 패키지로 먼저 추출)"이라 적었으나, E2 태스크 분해에는 공용 패키지 추출 태스크가
  없다([E3](E3-parallel-schedule.md) §H 리스크 표가 적발·판단, 완료 보고로 조율자에 기록 위임).
- **원 계획 인용**: 08 §A 병렬성 문단(W1·W2 독립 + 괄호 단서).
- **채택안**: 08 원문의 괄호 단서는 병렬화를 가능케 하는 **선택적 최적화 아이디어**이지 필수 선행조건이 아니다.

  구현**으로 진행한다. 근거: ① 공용 패키지化는 G3 단독 슬롯을 강제해 오히려 병렬성을 해침, ② 두 앱의 auth
  패턴은 reporter→control-center 동형 이식으로 이미 검증돼 있어 독립 구현이 더 단순·안전, ③ 파일 소유권이
  `apps/reporter/src/auth/*` vs `apps/control-center/src/auth/*`로 배타적이라 병렬 배치에 지장 없음(E3 웨이브
  편성 참조).
- **영향 문서**: 08 무변경(마스터플랜 자체를 바꾸지 않는 실행계획 단계 해석 확정). E2 T-W2-01/T-W2-04·E3 해당
  웨이브 편성이 이 해석을 이미 반영. 대장 등재는 PIVOT-PLAN §6-11.

## EXEC-DECISIONS #3 — 웨이브 토큰 상한 145만 → 200만 상향 (2026-08-04, EXEC-EVAL-ROUND-1 X-12 · E4 §G 라운드 1 제출분)

- **배경**: 舊 상한 145만은 **qa-verifier(게이트②) 비용을 전혀 계상하지 않은 합계** 위에서 산정된 값이었다

### ② 환경변수 예제 파일 동시 소유 — G3 위반 (조율자 편성 실수)

- **사실**: 조율자가 Wave 2의 **4개 위임 전부**에 "환경변수 예제 파일에 키 이름만 추가 허용"을 넣었다.
  실제로 **3개 태스크가 동시에 편집**했다 — T-W0-01(`WEB_ORIGINS`)·T-W0-02(`S3_CORS_*` 3종)·
  T-W0-04(백업 키 8종 + `GACHINOL_DOMAIN`).
- **위반 조항**: **G3**("동시 실행 태스크는 파일 집합이 겹치지 않아야 한다"). 파일 소유권 배타를 조율자가
  **위임 단계에서 스스로 깼다** — 에이전트의 이탈이 아니다.
- **실제 피해**: **0건**. 세 태스크가 전부 파일 끝/서로 다른 섹션에 append했고 rewrite가 없어 손실이
  발생하지 않았다(실측: 3구간이 모두 실재). **다만 이는 운이며 규칙의 성립이 아니다** — 한 곳이라도
  전체 재작성을 했다면 나머지가 소실된다.
- **재발 방지**: 환경변수 예제 파일을 **준-공용 자산으로 지정**한다(루트 `pnpm-lock.yaml`·`app.module.ts`와
  동형 — E3 §B 준-공용 자산 개념 원용). **동시성 1**: 한 웨이브에서 이 파일을 편집하는 태스크는 1건만
  배치하고, 2건 이상이 키를 추가해야 하면 **조율자가 웨이브 종료 후 취합해 단독 커밋**한다.
  SOLO 승격은 불요(lockfile과 동일 취급). → **Wave 3부터 위임 프롬프트에 이 제약을 명시한다.**
- **E5 §A "위반 시 조치" 적용**: 본 항이 그 2항("위반 사실을 EXEC-DECISIONS에 1건으로 기록 — 무엇이
  누락됐는지 구분")의 이행이다. 유형 = **"게이트 로그 누락"이 아니라 "편성 규칙 위반"**이며, 적발 주체는
  조율자 자신(웨이브 진행 중 `git status` 실측). **태스크 원복은 불요** — 산출물 자체는 정상이고 위반은
  편성 층위에서만 발생했다.
