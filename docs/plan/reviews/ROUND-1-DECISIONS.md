# 라운드 1 수정 — 문서 횡단 확정 결정 (조율자 발행)

> EVAL-ROUND-1의 문서 간 정합성 이슈에 대한 **단일 결정**. 모든 수정 에이전트는 이 결정을 따른다.
> 이 결정과 어긋나는 문서 내용은 이 결정에 맞춰 고친다. (수정 완료 후 PIVOT-PLAN.md 결정 로그에 D10~로 편입)

## X1. VOD 생존 주장 정정 + 공개 렌디션 서빙 보강 (C2 해소 — 02·04·08 공통)

- **사실 정정**: 현행 코드는 피드 목록·재생 서명 URL을 api(`GET /v1/feed`, `s3.presignGet`)가 발급한다. 따라서 **제온(api) 다운 시 VOD 신규 재생도 중단**된다. "VOD 시청 생존" 주장은 전 문서에서 삭제·정정한다. 생존하는 것 = Cloudflare 캐시된 정적 웹 + **진행 중인 라이브 시청(CF Stream)** + 이미 발급된 서명 URL의 잔여 유효시간뿐.
- **보강 결정(신규 설계 항목, W2 범위)**: published 콘텐츠는 어차피 공개다 → **공개 렌디션 전용 버킷(또는 접두사) 분리 + Cloudflare 커스텀 도메인 캐시 서빙**으로 전환한다. 송출 시 720p 렌디션·썸네일을 공개 경로로 복사(멱등)하고 피드가 공개 URL을 내려준다. 효과: ① 제온 다운 시에도 **직전 캐시된 피드 + 공개 URL 재생 생존** ② api 서명 부하 제거. 원본·프리뷰(비공개 단계)는 현행 서명 URL 유지.
- 04·08의 생존 매트릭스는 "보강 전(현행)"과 "보강 후(W2+)" 2단으로 나눠 정직하게 기재한다.

## X2. 클라우드 전환 트리거 단일화 (C1 해소 — 05·08)

- **05 §C가 트리거의 유일 원천이다.** 08 §C는 자체 수치를 갖지 않고 05 §C를 참조만 한다.
- 구조: **컴포넌트 단위 조기 이관**(가용성·성능 등 기술 트리거 1건 충족 → 해당 컴포넌트만 이관)과 **전면 전환**(05의 트리거 중 2개 이상 동시 충족)을 명시적으로 구분한다. 재무 수치는 05의 것(월 총매출 800만원×3개월 등)을 채택하고 08의 "월 순수익 22~35만원" 계열 수치는 삭제한다.

## X3. 후원·멤버십 × 쉘 앱 IAP 충돌 해소 (05·07·02)

- **결정: 쉘 앱(웹뷰) 안에서는 디지털 재화(후원·멤버십) 결제 동선을 노출하지 않는다.** 웹앱이 쉘 UA/파라미터를 감지해 후원 메뉴를 숨긴다(리더 앱 모델). 실물 커머스는 Apple 3.1.1/Play 정책상 웹결제 허용이므로 쉘 내 노출 유지.
- 02 D-T2(쉘 책임)에 "쉘 내 디지털 재화 비노출" 1줄, 05(후원 축)와 07(§1 스토어)에 이 결정을 반영한다.

## X4. TTFF 단일 정의 (02·03·04)

- **정의: TTFF = 카톡 링크 탭 → VOD 첫 프레임, p75 ≤ 4초 (LTE·카카오 인앱 브라우저 기준).** 정본은 02 §C 성능 예산이며 03·04는 참조만 한다.
- 라이브의 지연 지표(글래스투글래스 등)는 **별개 지표**로 04가 소유한다 — TTFF와 혼용 금지. 03의 "3초", 04의 "15초" 등 상이 수치는 위 정의로 통일하거나 별개 지표로 명확히 개명한다.

## X5. 주민 제보 경로 단일 설계 (01·02·03·08)

- **결정: 주민 제보 = 지사 담당자가 발급하는 임시 업로드 링크**(03에서 제안된 안 채택). 주민은 로그인 없이 링크로 촬영·업로드(간단 모드) → 지사 기자가 검수·장면 정리 후 정식 콘텐츠로 편입. `ContentOrigin` 확장 등 스키마 작업은 실행계획 항목으로 W2에 편입(02 §E·08 W2에 구현 항목 추가).
- 01의 주민 참여 KPI는 이 기능의 W2 가동 이후 시점으로 조정한다(존재하지 않는 기능에 KPI 금지).

## X6. 업로드 멀티파트 승격 트리거 단일 문장 (01·02)

- **"업로드 실패율 주간 5% 초과 또는 평균 원본 크기 300MB 초과 시 멀티파트로 승격"** — 이 문장을 02 D-T4가 소유하고 01은 인용만 한다. 다른 수치(15%/85% 등)는 삭제.

## X7. 02 사실 오류 정정 (영역 1)

- 앱 단위 테스트 수는 **303건**(reporter 74 + control-center 153 + subscriber 48 + media-worker 13은 앱 아님 — 정확 수치는 리포에서 재확인해 기재)으로 정정.
- 업로드 계층: 현행 `HttpUploadService`는 expo-file-system 업로드 태스크 기반 = **웹 미지원**. "✅ fetch/XHR 그대로"를 "**웹용 업로더 어댑터 신규 작성 필요**(XHR 진행률/취소, 기존 `useUploadService()` DI 지점에 웹 구현 주입)"로 정정하고 재사용 판정표의 수정 대상에 명시.
- Expo Web 활성화 선행조건 신설: `react-dom`·`react-native-web` 의존성 추가, app.json `web` 블록, metro 웹 설정 — 3앱 공통 선행 작업으로 02 §E 체크리스트 최상단에 추가.
