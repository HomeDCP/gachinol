05가 "낙관 시나리오조차 12개월 내 완전손익분기에 도달하지 못한다"고 자기 결론을 뒤집은 것,

그럼에도 통과선을 못 넘는 이유는 **하나의 반복 패턴** 때문이다 — **발주는 했는데 수신이 안 됐고,

- **실제 미수신 4건**: 미성년자 촬영 플래그(07→02/03, 2라운드 연속), 광고주 리포트 집계통계 원칙(07→05,

  **같은 유형의 오류를 그대로 반복**했다.
- **수치 이중 정의 1건**: 라이브 방송시간 모수가 04(커머스 2h/회, 월 24·32·56h)와 05(커머스 1h/회, 월
  21.3·25.3·37.3h)에서 다르다. 이 수치는 04 SLO#1의 허용 중단 예산과 05의 CF Stream 비용을 동시에 결정하는
  **공유 모수**인데, 04는 "05 어디에도 명시돼 있지 않아 2시간으로 가정한다"고 적었고 05는 실제로 1시간을 명시했다.
  ROUND-1 X2·ROUND-3 Z3가 확립한 "단일 원천" 규율이 이 항목에는 적용되지 않았다.

여기에 영역별 고유 결함이 얹힌다: 05는 12개월 내내 적자인데 **자금 조달·누적 적자 상한이 어디에도 없고**,

## ③ 영역별 상세

### 영역 1. 실행 가능성 — **9.3**

**주 근거**: 02, 08

**충족 확인(감점 없음)**: Expo Web 선행조건 3건이 실측으로 "현재 미충족"임을 명시하고 §E 0번에 선행 항목으로
못박은 점, `metro.config.js`가 이미 존재하므로 "신규 생성이 아니라 확장"이며 pnpm `disableHierarchicalLookup`
금지 주석을 보존해야 한다는 함정까지 기재한 점, 재사용률 산정식을 파일 수 단위로 공개하고 3앱/전체를 분리
표기한 점, §E 0~19번 **전항목에 담당·기한**이 붙은 점, 08 W1 DoD가 "지정 실기기 3종 × 카카오 인앱 × LTE ×
각 20회, 합산 p75 ≤4초"로 **측정 프로토콜까지 고정**한 점, W0 방화벽 승인에 "+4주 미승인 시 Cloudflare Tunnel
단독안 자동 확정"이라는 데드라인형 자동 결정을 건 점은 모두 9.5 앵커를 충족한다.

**감점 사유**

1. **최상위 기술 가정의 검증 시점이 문서 간 상충하고, 이른 시점의 수신 슬롯이 없다.**
   07 §1-3은 `<input capture>` 대용량 파일(0.5~1GB) 업로드 안정성·iOS Safari 탭 discard·카톡 웹뷰 동작을
   "가장 리스크 큰 가정이므로 선검증", 기한 "웹 피벗 스캐폴딩 착수 직후, **다른 화면 구현보다 먼저**"로 지정하고
   §6 "즉시" 블록에 넣었다. 그러나 02 §E 7번은 이 검증을 **W2**로, 03 실행 체크리스트도 **W2 착수**로 배치한다.
   02 §E·08 §E 어디에도 W1 이전에 수행되는 `<input capture>` PoC 항목이 없다 — 07이 "선검증"이라 부른 것의
   실행 슬롯이 계획 어디에도 존재하지 않는다.
2. **법정 게이트 1건이 구현 슬롯 없이 2라운드째 표류한다.** 07 §3-3 액션 2(기자 앱 워크플로우에 "미성년자
   촬영 여부" 플래그 + 승인 단계 법정대리인 동의서 첨부 확인 게이트)는 02·03에 발주됐으나, 두 문서 전체에
   "미성년자"·"법정대리인" 문자열이 **0건**이다(grep 확인). 07 §6은 이를 "재발주·추적" 항목으로 등재했지만
   **기한이 없다**(담당만 표기).
3. **04가 정의한 라이브 가용성 완화책의 기술 전제가 02/08에 미등재.** 04 §B④ "라이브 신규 진입 완화책"은
   "웹앱 정적 배너(방송 편성표 페이지, 정적 자산이라 api 무관 생존)"에 HLS URL을 직접 포함하는 것을 전제로
   하는데, 02 §B 신규 파일 목록·§E 체크리스트·08 §A/§E 어디에도 "편성표" 페이지가 없다(grep 0건).
4. **04 §H-1 게이트 13번의 08 위임이 미수신.** 04는 "Meta App Review + Business Verification 신청을 08 §E에도
   동일 항목 등재 요청"이라 적었으나 08 §E(1~9번)에 해당 항목이 없다. (08 §A 시간축 매핑표 앵커 3이
   "04 §H-1 전항목 통과"를 첫 실 방송 게이트로 인용하고 있어 **게이트 자체는 유지**되므로 감점은 경미.)

**9.5 도달 수정 지시**

- (a) 02 §E에 **W1 이전 선행 항목**으로 `<input capture>` 대용량 업로드 실기기 PoC를 신설한다 —
  "iOS Safari·Android Chrome·카카오 인앱 웹뷰 3환경에서 500MB·1GB 파일 각 3회 선택→업로드,
  탭 discard 재현 시 재개 성공 여부 기록", 담당: FE 리드, 기한: **W1 착수 전(실패 시 07 §1-3 대안 발동 검토)**.
  동시에 07 §1-3·§6과 03 실행 체크리스트의 기한 표기를 이 항목 번호로 통일한다.
- (b) 02 §E에 "미성년자 촬영 여부 플래그 + 승인 단계 법정대리인 동의서 첨부 확인 게이트"를 항목으로 신설하고
  (담당: BE 리드+FE 리드, 기한: **첫 촬영 재개 전** = 08 매핑표상 W2 DoD 직전), 03 §C에 해당 입력 UX를 등재한다.
  07 §6 추적 항목에도 동일 기한을 부여한다.
- (c) 02 §B 신규 파일 목록과 §E에 "정적 방송 편성표 페이지(라이브 HLS URL 직접 게시, api 비의존)"를 추가하고
  재사용률 산정표의 신규 파일 수를 재계산한다(현재 16 → 17). 04 §B④는 그 항목 번호를 인용한다.
- (d) 08 §E에 "Meta App Review + Business Verification 신청(04 §H-1 게이트, 담당 PO+테크리드, 기한: 사업자등록
  완료 직후)"을 항목으로 추가한다.

### 영역 2. 서비스 성립성 — **9.3**

**주 근거**: 01, 02

**충족 확인(감점 없음)**: 01 §A-1이 파이프라인 8단계를 "현재 구현 / 웹 전환 후 / 성립 근거" 3열로 대조하고
**9행(자동편집)을 루프 밖 T-AI-2로 분리**해 "성립 논증에 포함하지 않는다"고 선언한 것은 이 계획에서 가장
정직한 서술이다. §A-2의 "잃는 것" 4종에 손실 정도·관리방안·잔여 리스크를 각각 붙이고, "얻는 것"의 유지보수
절감(9곳→1곳)에 대해 **비용 상계 절**(브라우저 매트릭스 회귀·hls.js 회귀·정책 추적 월 20~30h 가정)을 스스로
신설해 절감 주장을 반쪽으로 인정한 것도 앵커 충족이다. §A-5 리스크 6건 전부 완화책·담당·트리거 3요소를 갖췄고,
"제온 다운 시 신규 VOD 시청 불가"를 보강 전/후 2단으로 정직 기재한 점도 좋다.

**감점 사유**

1. **01 §A-6 실행 체크리스트 8개 항목 중 담당·기한이 있는 것은 1건뿐이다.**
   ("Service Worker 오프라인 캐시 PoC — 담당: 웹 프론트엔드 리드, 기한: W2 착수 전" 1건. 나머지 7건 —
   presigned 청크 재개형 재설계 요구 전달, 이탈 방지 배너 UX 초안, `<input capture>` 기본 경로 확정,
   홈화면 추가 배너 요구사항 전달, VOD 보강책 W2 요구사항 전달, T-AI 등재 확인 — 은 오너가 없다.)
   03·04·05·06·02·08이 모두 전항목 담당·기한을 채운 것과 대비되며, RUBRIC의 "오너 없는 액션" 감점 대상이다.
2. **03이 01·02의 사실 정정을 승계하지 않아 성립 논거가 문서 간에 엇갈린다.**
   02 §A 실사표는 현행 업로드 계층을 "❌ 웹 미지원 → 웹용 업로더 어댑터 신규 작성 필요"로 판정했고 리포 실체도
   그렇다(`expo-file-system/legacy` `createUploadTask`). 그런데 03 §C-3은 여전히
   "현재 `http-upload-service.ts`(presigned PUT + 진행률 + `AbortController` 취소)는 **웹 `fetch`로도 동작 가능하나**"
   라고 서술한다. 웹 전환의 난이도를 문서마다 다르게 제시하는 것은 성립성 논거의 신뢰를 깎는다.
3. **01 §A-4 "iOS A2HS 전환율 3개월 15% / 6개월 30%"의 근거가 얇다.**
   03 §A-5·§D는 A2HS 배너를 "영상 1회 시청 후 닫을 수 있는 1회성 배너, 거절 시 영구 숨김, 카톡 인앱에서는
   아예 비노출"로 설계했다. 이 노출 정책에서 6개월 30% 전환은 "가정"이라는 표기만으로는 지탱되지 않는다
   (트리거는 "3개월 <10%" 하나뿐이라 30% 목표 자체는 검증되지 않는다).

**9.5 도달 수정 지시**

- (a) 01 §A-6 전 항목에 담당·기한(또는 W단계)을 부여한다. 특히 "요구사항 전달" 성격 항목은 **전달처 문서·절 번호**와
  수신 확인 방법(예: "02 §E에 항목 존재 여부 grep")까지 적어 위임 누락을 구조적으로 막는다.

**9.5 도달 수정 지시**

### 영역 5. 콘텐츠 확보 용이성 — **9.2**

**충족 확인(감점 없음)**: "Scene 구조가 UI 가이드가 아니라 **타입 계약**이라 우회 불가 → 품질 하한을 코드가

2. **01 §C-8 실행 체크리스트 8개 항목 중 담당·기한이 있는 것은 1건뿐이다.**

   항목의 기한을 인용하며, **항목 번호가 확정되는 대로 본 절에 반영한다**"고 적혀 있으나, 02 §E 16번(콘텐츠 소비

### 영역 6. 고령층 사용성 — **9.3**

**주 근거**: 03

**충족 확인(감점 없음)**: WCAG 2.2 AA 항목별 요구치와 자체 목표치(본문 7:1 대비, 44×44pt 타깃)를 표로 확정하고

2. **§A-1의 "큰 자막 모드 기본값" 표기가 §A-3·§B-1과 정합하지 않는다.** §A-1은 "큰 자막 모드(토글,

3. **미성년자 촬영 플래그(07 §3-3 액션 2) 미수신** — 03 실행 체크리스트에도 관련 항목이 없다(영역 1 감점 2와
   동일 사실). 03은 공급자 UX(촬영 위저드)의 정본이므로 수신처 후보 중 하나다.

**9.5 도달 수정 지시**

- (a) §C-3 첫 문장을 02 §A 실사표 판정과 동일하게 교체한다(영역 2 지시 (b)와 동일).
- (b) §A-1 괄호 문구를 확정 문장으로 교체한다 — 예: "큰 자막 모드는 **기본 OFF, 상시 노출 토글**이며,
  자동 자막(캡션 표시)만 기본 ON이다. 사용자가 한 번 켜면 `localStorage`로 유지한다." §B-1 과업 2·KPI와의

- (c) 03 §C(촬영/자막 입력)에 "미성년자 피촬영자 플래그 입력 + 법정대리인 동의서 첨부 안내" UX를 신설하고

### 영역 9. 소통창구 관리 — **9.4**

**주 근거**: 06 §B

**충족 확인(감점 없음)**: "시청자가 라우팅을 고민하게 하지 않는다"는 대원칙 아래 접수→기록→이관을 다이어그램으로
확정하고, **이관 2시간 이내 + SLA 시계는 접수 시각 기준 유지 + 회신 책임은 접수자에게 잔류**라는 3규칙을 못박은
것이 핵심이다. 출연자·판매자 창구를 시청자 창구와 분리하고 클레임성/비클레임 SLA를 나눈 점, "신규 도구 도입
최소화" 원칙의 성립 조건(카카오 채널 관리자 도구의 **다채널 통합 인박스 지원 여부**)을 가정으로 두지 않고
**W1 실측 검증 항목**으로 만들고 미지원 시 대체안 3종과 그 발동 조건·결정권자·비용까지 정한 점, 대장 입력 누락을
채널별 대사(괴리율 >10%)로 계측하는 점, 지사 5개 초과 시 스케일 규칙, B2B 창구의 국면 분리(01 발굴 / 05 전담 /
06 1차 접수)는 모두 앵커 충족이다.

**감점 사유**

1. **어르신 1차 채널로 승격된 "지사 담당자 직통 전화"가 개인 소지 회선인데, 그에 따른 리스크가 미검토다.**
   06 §A는 이 회선을 "지사 담당자(자기 지사, **개인 소지 회선**)"로 명시하고, 03 §B-3은 그 번호를 **큰 글씨
   리플렛에 인쇄해 배포**하며 03 §A-6은 재생 실패 폴백 화면에 **[전화로 문의하기] 버튼으로 상시 노출**한다.
   개인 번호를 공개 채널로 광고하는 데 따르는 ① 개인정보(담당자 본인의 연락처) 취급 근거 ② 퇴사·교체 시 번호
   승계·리플렛 회수 ③ 근무시간 외 사적 수신 부담의 처리가 06·07 어디에도 없다. 07 §5-4 약관/처리방침 필수
   조항 체크리스트에도 이 항목이 없다.
2. **06→05 인건비 편입 요청이 미수신.** 06 §A는 전담 CS 채용 시 월 150~200만원을 산정하고 "05 §H가 명시한
   갱신 대상에 이 수치를 편입 요청한다"고 적었으나, 05 §B-3 인건비 표에 CS 라인이 없다(05 §H의 일반 문장만
   존재). 트리거 미도달이라 영향은 작지만 위임 수신이 닫히지 않았다.

**9.5 도달 수정 지시**

- (a) 06 §A "전화(지사 담당자 직통)" 행에 **회선 정책**을 명시한다: 업무용 번호 사용 원칙(개인 번호 사용 시
  본인 동의 서면 확보·사내 문서에만 보관), **담당자 교체 시 번호 승계 절차 및 리플렛 회수·재배포 규칙**,
  근무시간 외 수신 처리(부재중 → 당일 콜백). 담당·기한을 §F에 항목으로 추가하고, 07 §5-4 체크리스트에
  "지사 담당자 연락처 공개 게시의 동의·보유기간" 행을 추가한다.
- (b) 05 §B-3 인건비 표 또는 §G에 "전담 CS 채용(트리거: 06 §A 월 300건 또는 SLA 위반율 20% 2개월 연속) 시
  월 150~200만원 추가"를 **조건부 인건비 행**으로 등재한다.

### 영역 10. 클레임 해결 — **9.1**

**주 근거**: 06 §C, 07 §5

**충족 확인(감점 없음)**: 클레임 7유형(초상권·오보·커머스·기술·채팅신고·**제3자 저작권 스트라이크**·**라이브 중
실시간 오보**)에 1차 조치 SLA·처리 절차·에스컬레이션이 모두 붙었고, §C①은 정보통신망법 제44조의2의 법정 요소
(지체 없는 조치·양측 통지·30일 임시조치·공시)를 절차 단계로 편입했다. **24시간 SLA의 야간·주말 접수 경로**
(카톡 상시 푸시 → 당번 지사 담당자 → 센터장 즉시 에스컬레이션 → 주말 관제 접근권한 사전 부여)를 별도로 설계한
점, 삭제 요청의 외부 채널 잔존을 "삭제 체크리스트 대장 필수 컬럼, 전 채널 확인 전 종결 불가"로 막은 점,
KPI에 측정 원천(`status_transition_logs` 비공개 전환 타임스탬프 ↔ 대장 접수 시각 월간 대사, 대장 미기록은
위반 계상)까지 붙인 점, **3선(외부 법률자문) 미계약 상태에서는 에스컬레이션이 실행 불가임을 인지하고 센터장
잠정 대행을 명시**한 점은 앵커 충족이다.

**감점 사유**

1. **02 §D-T8이 새로 만드는 삭제 표면이 클레임 절차에 반영되지 않았다.** D-T8은 W2에 published 콘텐츠의 720p
   렌디션·썸네일을 **공개 전용 버킷으로 복사하고 Cloudflare 커스텀 도메인 캐시로 서빙**한다("공개 URL은 만료
   없음", 04 §B④ 표). 그런데 06 §C① 삭제 절차·§E "삭제 요청의 외부 채널 잔존" 리스크·07 §5-2 4항의 외부 사본
   목록은 모두 **"자체·YouTube·카톡 12채널"**까지만 다루고 **공개 버킷 객체 삭제·CF 캐시 퍼지(purge)**가 없다.
   24시간 임시 비공개를 실행해도 공개 URL과 엣지 캐시가 살아 있으면 조치가 실효하지 않는다 — KPI가 "100% 준수"
   인 항목에서 이는 구조적 구멍이다.
2. **§C① B2B 회수 절차가 존재하지 않는 계약 조항에 근거한다.** "05 §A-2 B2B 계약서상 회수·방영중단 협조
   조항에 근거해 구매처에 공문 발송"이라 적혀 있으나 05에 해당 조항이 없다(영역 3 감점 1·영역 4 감점 1과 동일 사실).
3. **§C KPI가 커머스 1/2단계로 분리돼 있지 않다.** §C③ 처리 절차는 Z1에 맞춰 1단계(외부 플랫폼 안내)/2단계로
   재구성됐는데, KPI 줄은 여전히 "커머스 분쟁 GMV 대비 <1%(측정 원천: **GMV = PG 정산 리포트**)"와
   "청약철회 처리 완료율 ≥95%"를 단계 구분 없이 제시한다. 1단계에는 PG도 정산 리포트도 없고 청약철회 처리
   주체도 외부 플랫폼이므로 **MVP 기간 내내 측정 불가능한 KPI**다.

**9.5 도달 수정 지시**

- (a) 06 §C① 삭제 체크리스트와 §E 리스크 행에 **"공개 렌디션 버킷 객체 삭제 + Cloudflare 캐시 퍼지"**를 필수
  단계로 추가하고(담당: BE 리드, 확인 책임: 센터 운영자), 02 §D-T8·§E 14번에 **"삭제/비공개 전환 시 공개 객체
  제거 및 캐시 무효화 경로 구현"**을 구성 요소로 명시한다. 07 §5-2 4항의 외부 사본 목록에도 같은 항목을 추가한다.
- (b) 05 §A-2 실행조건 4에 회수·방영중단 협조 조항을 등재한다(영역 3 지시 (a)와 동일).
- (c) §C KPI 줄을 단계별로 분리한다 — 1단계: "외부 플랫폼 안내·판매자 연결 완료율 ≥95%(측정: 대장 유형③)",
  2단계: 기존 GMV 대비 분쟁률·청약철회 완료율(측정 원천 PG 정산 리포트). 각 KPI에 발효 시점(1단계 즉시 /
  2단계 진입 후)을 표기한다.

### 영역 11. 법률·라이선스 — **9.1**

**주 근거**: 07

**충족 확인(감점 없음)**: 스토어 정책은 Apple 4.2·Google 4.3을 각각 다루면서 **리젝 대응 종료 규칙**
(1차→플랜 B, 2차→iOS는 PWA 단독 확정)까지 못박았고, 특히 **"Lighthouse PWA 카테고리는 v12에서 제거됐으므로
'PWA 점수 80 이상' 게이트는 애초에 구현 불가능하다"**며 자기 이전 요구를 폐기하고 installability 구조 검사로
대체한 것은 이 문서의 백미다(리포·업계 사실과도 부합). OSS 인벤토리는 리포 실측과 일치하며
(`ffmpeg-static`/`ffprobe-static`, xeon 오버레이의 MinIO, `redis:7-alpine` — 전부 확인),
FFmpeg GPL 판단을 "conveying 미발생 + `child_process` 분리 실행"이라는 2중 방어선으로 정리하고
**실제 노출 지점 2개(GHCR public 전환·제품화 재판매)**를 특정한 뒤 가시성 고정·라이선스 텍스트 보관·전환
시나리오를 액션으로 만든 것은 정확하다. 국내 규제 15절(방송법 비적용, 부가통신 신고, 개인정보, 전자상거래
2026 개정, 언론중재법 지위 부재의 양날, 초상권 판례, 원산지 형사처벌, 불법촬영물 2026 확대, 저작권 재판매
체인, 국외이전, 접근성, 표시·광고, 선거, 쿠키·행태정보, 무인증 업로드)은 커버리지가 넓고 각 절에 담당·기한이
붙어 있다. §5-4 약관/처리방침 필수 조항 11행 집계표, §6 시점별 종합 체크리스트도 앵커 충족이다.

**감점 사유**

1. **자기 선언한 재발 방지 원칙을 그대로 위반한 오참조가 2건 남아 있다.** 07은 라운드 3에서
   "항목 번호가 아니라 **항목 제목으로 grep**한다"는 원칙을 세웠는데(§1-4·§3-15),
   ① §1-2 말미는 "installability 구조 검사는 … **02 §E 실행 체크리스트에는 아직 항목으로 등재되지 않은
   상태다**"라고 서술한다. 실제로는 **02 §E 18번**에 "CI installability 구조 검사 … **07 §1-2 재작성안 수신** —
   담당: 테크리드, 기한: TWA 패키징(10번) 착수 전"으로 등재돼 있고 02 §C 성능 예산 표에도 반영돼 있다.
   ② §6 "발주 수신 확인 추적"은 "03 §A-2 쿠키 잠정 원칙 반영 재요청"을 미수신으로 등재하나, 03 §A-2에는
   해당 블록쿼트("07 §3-14 판정 전까지 잠정 원칙")가 이미 들어가 있다. **수신 완료된 항목을 미수신으로 기재하면
   불필요한 재작업을 유발하고, 추적표 자체의 신뢰가 무너진다.**
2. **§6 "발주 수신 확인 추적" 4개 항목에 기한이 없다.** 담당(PO 발주 + 수신 문서 담당)만 있고 언제까지
   수신을 완료해야 하는지가 없다. 이 중 2건(05 집계통계, 02/03 미성년자 플래그)은 **실제로 2라운드 연속
   미수신**이므로, 기한 없는 추적은 다음 라운드에도 같은 상태로 남을 개연성이 크다.
3. **§6 "즉시" 블록의 시점이 다른 문서와 어긋난다.** ① installability CI 게이트를 "즉시"에 넣었으나
   02 §E 18번·§C는 "TWA 패키징(W3) 착수 전"이다. ② `<input capture>` 실기기 검증도 "즉시"인데 02 §E 7번·03은
   W2다(영역 1 감점 1). 07 §1-2 본문은 "웹 3종 스캐폴딩 완료 직후"라 §6 "즉시"와 07 내부에서도 불일치한다.
4. **개인 연락처의 공개 게시가 법적 검토 대상에서 빠졌다.** 06 §A(지사 담당자 개인 소지 회선)·03 §B-3(번호를
   인쇄한 리플렛 배포)·03 §A-6(폴백 화면 상시 노출)이 확정됐는데, §3-3(개인정보)·§5-4(처리방침 필수 조항)
   어디에도 담당자 본인 연락처의 수집·공개·보유기간 처리가 없다(영역 9 감점 1의 법률 측면).

**9.5 도달 수정 지시**

- (a) §1-2 말미의 "02 §E에 미등재" 서술을 **"02 §E 18번에 등재 완료(담당 테크리드, 기한 TWA 패키징 착수 전)"**로
  갱신하고, §6 추적 항목에서 installability·03 §A-2 두 건을 **"수신 확인 완료"로 종결 처리**한다. 남기는 경우
  체크박스를 [x]로 바꾸고 확인 일자를 기재한다.
- (b) §6 추적 항목 중 실제 미수신 2건(05 §A-3 집계통계 원칙, 02/03 미성년자 플래그)에 **기한과 미수신 시 조치**를
  부여한다 — 예: "기한: W1 착수 전. 미수신 시 해당 기능(광고주 리포트 제공 / 촬영 승인 게이트)의 착수를
  보류한다." 담당은 발주자(PO)와 수신 문서 소유자 양쪽을 병기한다.
- (c) §6 "즉시" 블록을 **다른 문서의 W단계 표기와 일치시킨다**(installability → "TWA 패키징 착수 전(02 §E 18번)",
  `<input capture>` 검증 → 영역 1 지시 (a)로 신설되는 W1 이전 PoC 항목 번호). 07 §1-2 본문의 "스캐폴딩 완료
  직후"도 같은 값으로 통일한다.
- (d) §3-3 또는 §5-4에 **"지사 담당자 직통 번호의 공개 게시"** 행을 신설한다(본인 동의 서면·업무용 회선 원칙·
  교체 시 회수 절차·처리방침 기재 여부, 담당: 외부 법률자문+센터 운영팀, 기한: 03 리플렛 제작 전).
