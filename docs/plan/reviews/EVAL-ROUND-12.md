### 영역 2. 서비스 성립성 — 9.5

**충족 근거**: 01 §A-1이 파이프라인 8단계를 현재 구현과 1:1 대조해 "루프가 끊기는 지점 없음"을 논증하고,
성립 논증 대상(1~8행)과 루프 밖 트랙(9행 `auto_edit`)을 분리해 **미구현 기능을 성립 근거로 쓰지 않는다**.
잃는 것 6종(백그라운드 업로드·카메라 세밀제어·오프라인 촬영·푸시·백그라운드 오디오·오프라인 시청)에
각각 손실 정의·관리방안·잔여 리스크가 붙고, 그중 오프라인 시청은 "현행 네이티브도 미제공 → 신규 손실
아님"으로 **검토 후 종결** 처리했다. §A-4 KPI는 실측 전 잠정치임을 표기하고 재설정 담당(백엔드 담당)·
기한(W2 착수 +3개월)·미달 시 조치(완료 시간 초과 시 멀티파트 조기 착수, 판정 W1 완료 +2주)를 명시한다.
§A-5 리스크 7행 전건에 완화책·담당·트리거 3요소가 있고, 최대 리스크(제온 다운 시 VOD 신규 진입 0)는

### 영역 11. 법률·라이선스 — **9.3**

**충족 근거**: 커버리지 자체는 매우 넓고 깊다. 스토어 정책(4.2/4.3)에 리젝 대응 **종료 규칙**(1차→플랜 B,
2차→iOS는 PWA 단독 확정, Android는 보강 후 재제출·2회 연속 시 트랙 재검토)이 있고, Lighthouse PWA
카테고리가 v12에서 제거돼 舊 게이트가 **실행 불가능**했음을 스스로 발견해 installability 구조 검사로
대체한 뒤 02 §C·§E 18번에 수신까지 확인했다. OSS 인벤토리는 실측 기반이며 최상위 리스크(FFmpeg GPL)를
"conveying 미발생 + `child_process` 분리 실행"이라는 2중 방어선으로 분석하고 실제 노출 지점 2개(GHCR
가시성, 제품화 판매)를 지목해 각각 액션·담당·트리거를 부여했다. Redis 트라이라이선스·MinIO AGPL도
Valkey 교체·R2 전환이라는 저비용 제거책으로 닫았다. 국내 규제는 16개 절로 방송법 비적용부터 청소년보호
책임자·무회원 약관 편입(브라우즈랩 한계를 감추지 않고 "리스크로 보유"라고 명시)·근로자성·유출 통지까지
다루며, §5-4 필수 조항 체크리스트 15행이 흩어진 약관 요구를 한곳에 모아 발주 첨부 규칙까지 정했다.
KWCAG 소급 반영에도 2단 분리 + 지연 상한 2주 + 08 §D 이관이 붙었다.

**감점 사유**

1. **X3(쉘 내 디지털 재화 비노출) 예외의 03 미수신 + 07 자체 발주 추적 규칙 미적용.** 07 §1-4는 이 결정을
   "02 §D-T2·03 §D의 '쉘 전용 기능 금지' 원칙에 대한 **유일한 예외로 허용**"이라 규정했으나, 03에는 이
   예외가 존재하지 않는다(`grep "후원\|멤버십\|쉘 UA\|X3" 03-accessibility-ux.md` → 0건, 실측). 07 §1-4
   액션 ②는 02 §E 11번 수신만 확인하고 **03향 예외 반영은 발주도, §6 추적 블록 등재도 하지 않았다** —
   07 §6이 라운드 8에 스스로 의무화한 "07이 새 발주를 만드는 절마다 같은 라운드 안에 추적 블록에 행을
   추가한다"와 라운드 10 "이월 금지 단서"가 이 건에는 적용되지 않은 것이다. 결과적으로 IAP/4.2라는
   **이 계획의 최상위 리젝 리스크의 유일한 실효 완화책**이, 03의 코드 리뷰 기준("기능 분기 없음")에
   문언상 막히는 상태로 남아 있다.
2. **§5-8(상표·서비스명 검토, 라운드 11 신설)이 §6 종합 액션 체크리스트에 미등재.** 실측:
   `grep "상표\|KIPRIS" 07-legal-license.md` → §5-8 본문 5건, §6(1124~1323행) **0건**. §3-16·§5-6·§5-7·
   §3-14-1 등 다른 신설 절은 전부 §6의 해당 블록에 항목으로 등재돼 있어 **§5-8만 비대칭**이다. §5-8의
   기한("대외 런칭 전, 도메인 확정(08 W0)과 동시 착수 권장")과 미조치 시 비용(카톡 채널 12개·도메인·
   스토어 등재명 연쇄 변경)이 본문에 적혀 있는데도 실행 체크리스트에서 누락돼, 승인 후 실행 단계에서
   §6만 보고 움직이면 그대로 빠진다.

**9.5 도달 수정 지시**

- 07 §1-4 액션 ②에 **03향 발주를 신설**한다: "03 §D·실행 체크리스트의 '기능 분기 없음' 코드 리뷰 기준에
  X3 예외(쉘 내 디지털 재화 비노출)를 명문화하도록 요청 — 확인 방법: 03 grep `후원·멤버십`(또는 `쉘 UA`),
  담당 PO(발주)+03 문서 담당(반영), 기한 쉘 심사 제출 전." 동시에 §6 "발주 수신 확인 추적" 블록에 행을
  추가하고 그 라운드 안에 grep을 실행해 `[x] 수신 확인 완료` 또는 `미수신`으로 종결한다(이월 금지 단서
  준수). PIVOT-PLAN §6에도 동일 행을 등재한다(영역 1 수정 지시와 동일 행).
- 07 §6에 **"대외 런칭 전"(또는 "즉시" 블록 내 도메인 확정 연동)** 항목으로 §5-8을 등재한다:
  "[ ] 서비스명 선행 상표 조사(KIPRIS, 제9·35·38·41류) → 출원/수용 결정 기록 + 도메인·카카오 채널명·
  스토어 등재명 표기 일치 확인 (§5-8) — PO + 외부 법률자문, 기한: 대외 런칭(08 §A 앵커 4) 전, 착수는
  도메인 확정(08 W0)과 동시." 유사 상표 발견 시 서비스명 변경 결정을 **대외 런칭 전에 확정**한다는 게이트도
  같은 항목에 병기한다.
- (권고, 감점 사유 아님) 07 §6 서두에 "신설 절은 같은 라운드 안에 §6 해당 블록에 항목으로 등재한다"는
  **자기 점검 규칙**을 §6 발주 추적 규칙과 나란히 명시해, §5-8 유형의 누락이 규칙으로 잡히게 한다.
