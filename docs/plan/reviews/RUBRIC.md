# 웹 피벗 마스터플랜 — 루브릭 평가 기준

> 독립 평가 에이전트는 이 기준으로만 평가한다. 1~10점, **0.1 단위**. 전 영역 **9.5 이상**이 통과선.
> 평가자는 프로젝트 내부 맥락·이전 평가를 무시하고, `docs/plan/*` 문서와 리포지토리 실체만 근거로 삼는다.

## 공통 점수 앵커

| 점수대 | 의미 |
|---|---|
| ~6.9 | 치명적 결함·미검토 영역 존재. 계획대로 하면 실패 가능성 높음 |
| 7.0~8.4 | 방향은 맞으나 주요 리스크에 완화책이 없거나 실행 주체·시점이 모호 |
| 8.5~9.4 | 실행 가능. 일부 리스크의 완화책·검증 근거·트리거가 부족 |
| **9.5~10** | **치명 리스크 부재 + 식별된 모든 주요 리스크에 (완화책·담당·발동 트리거) 3요소 명시 + 수치/근거 제시 + 실행 체크리스트 존재. 남은 것은 '실행'뿐인 상태** |

주의: 9.5는 "완벽한 미래 보장"이 아니라 **"계획 문서로서 더 고칠 것이 없는 상태"**다. 불확실성 자체는 감점 사유가 아니며, **불확실성을 식별·완화·트리거 없이 방치한 것**이 감점 사유다. 반대로, 근거 없는 낙관·숫자 없는 주장·오너 없는 액션은 공격적으로 감점하라.

## 평가 절차 (평가자 지침)

1. `docs/plan/PIVOT-PLAN.md`(인덱스)부터 읽고 전 문서를 정독한다. 필요 시 리포 코드·CLAUDE.md·docs/*를 교차 검증한다.
2. 영역별로 **감점 사유를 구체적으로 인용**한다(문서명·섹션). "막연히 부족" 금지 — 무엇이 빠졌는지 지목한다.
3. 각 영역: 점수(0.1 단위) + 감점 사유 목록 + **9.5에 도달하기 위한 수정 지시**(실행 가능한 문장으로).
4. 결과를 `docs/plan/reviews/EVAL-ROUND-<n>.md`에 기록한다: 총평 → 점수표 → 영역별 상세.
5. 이전 라운드 평가문서는 읽지 않는다(독립성). 문서 개선 여부는 현재 문서만으로 판단한다.
