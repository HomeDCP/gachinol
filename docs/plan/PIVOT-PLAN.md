# Gachinol 웹 피벗 마스터플랜 (인덱스)

> 2026-08-03 수립. 네이티브 3앱(Expo RN) 체제를 **웹앱 3종 + 스토어 쉘 앱** 체제로 전환하는 계획의 최상위 문서.
> 본 계획은 독립 평가 에이전트의 루브릭 평가([reviews/RUBRIC.md](reviews/RUBRIC.md), 11개 영역 전부 9.5/10 이상)를
> 통과해야 확정되며, 확정·사용자 승인 후 실행계획을 별도 수립한다. **승인 전 코드 변경 없음.**

## 1. 전환 선언

| | 기존 | 전환 후 |
|---|---|---|
| 클라이언트 | 네이티브 앱 3종 (Expo RN, iOS/Android) | **웹앱 3종**(기자·관제·구독자, Expo Web으로 기존 코드 재사용) |
| 스토어 존재 | 앱 3종 각각 배포(예정이었음) | **껍데기 쉘 앱**(웹앱을 여는 래퍼) — 통합 1개 + PWA 병행 |
| 배포·업데이트 | 스토어 심사·버전 관리 | **웹 배포 즉시 반영**(심사 없음) — 유지보수 획기적 절감 |
| 접근·공유 | 설치 필요 | **URL만으로 접근·공유** — 카톡 채널 유입과 직결 |
| 인프라 | (동일) | **제온 서버 우선**, 클라우드 전환은 수치 트리거 기반(급격히 하지 않음) |

**바뀌지 않는 것**: 백엔드 전체(api·media-worker·ai-worker·shared 계약·DB), 제품 정의(12지사+센터, 콘텐츠 6종,
카카오 반자동 게시, 라이브 YT+FB), 편성 원칙, DCP 공존 규칙. 피벗은 **배포 형태의 전환**이지 제품의 전환이 아니다.

**전환의 이유** (사용자 결정, 2026-08-03):
1. 기개발 기능·로직을 그대로 웹에서 동작시켜 **앱 유지보수 업무를 획기적으로 축소**한다.
2. URL 기반 접근·공유 = "누구나 쉽게 찍어 올리고, AI가 편집해 방송국이 송출"하는 과업과 정합.
3. 제온 서버로 우선 운영하고, 비용·수익 관계가 정리된 뒤 클라우드 전환을 검토한다.

### 6-11. EXEC 단계 신규 위임 (실행계획 수립·실행 웨이브 — E5 §D 절차 4에 따라 신설)

> 실행계획([exec/EXEC-PLAN.md](exec/EXEC-PLAN.md)) 수립과 이후 실행 웨이브에서 발생하는 신규 위임을 여기
> 누적한다(새 대장을 만들지 않는다 — E5 §D "단일 원천 유지"). 등재 책임 규칙·Q1 원칙(확인=실행한 grep 결과만)은
> §6 본문과 동일하게 적용하며, 웨이브 종료 시 PMO가 등재 여부를 grep 재검증한다(E5 §D 절차 1).
> **EXEC 단계 수치(웨이브 상한·총예산·태스크 수 등)가 변경되면 §6-5 인용 대조 원칙을 연장 적용해 본 소절
> 상태 칸의 수치 인용도 전건 재검증한다**(EXEC-EVAL-ROUND-2 Y-10 — 상태 칸이 폐기 수치를 근거로 남는 SSOT
> 오염 재발 방지).
> **상태 칸의 건수·좌표는 확인 시점 스냅숏**(시점 명기 의무 — 이후 문서 진화로 값이 변해도 시점이 명시돼
> 있으면 stale이 아니다). E5 §D 앵커 ⑬은 확인 grep의 **존재 재현(1건 이상)만** 판정한다(라운드 11 N-8 —
> 건수 일치 요구는 D7-1 박제 금지와 충돌해 폐기).
