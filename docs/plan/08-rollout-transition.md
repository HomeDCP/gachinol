# 08. 전환 로드맵 · 제온 운영 · 클라우드 전환 트리거

> 평가 영역 1(실행 가능성)의 실행 순서 근거. 기술 설계는 [02-web-architecture.md](02-web-architecture.md).
> 실행계획(에이전트 편성·작업 분해)은 마스터플랜 **승인 후** 별도 수립한다 — 이 문서는 "무엇을 어떤 순서로"까지만 확정한다.

## A. 전환 단계 (W0~W4)

각 단계는 "한 바퀴 도는 것" 우선 원칙(기존 ROADMAP 철학 유지). **W1이 최우선** — 웹 피벗의 가치(URL 공유·설치 장벽 제거)가 가장 큰 곳이 구독자다.

**시간축 매핑표 (W단계 ↔ 마일스톤, EVAL-ROUND-3 영역 1 감점 4·정합성 이슈 C-15 해소)**

01·03·04·05·06·07은 "MVP 착수"·"MVP 착수 +N주"·"첫 촬영 재개 전"·"첫 실 방송 전"·"런칭 직전/4주 후"·"M1~M12"를
쓰고, 08은 W0~W4를 쓴다 — 두 축의 매핑이 없으면 다수 기한의 선후 판정이 불가능하다(예: 03 패널 R2·R3의 배치,
05 Kill Criteria "M6 말", 01 "W2 가동 이후 6개월"이 M 몇 월인지). 아래는 **기간 산정(주차 확정)이 아니라
의존관계 선언**이다 — 08은 여전히 "몇 주가 걸리는가"는 실행계획으로 이월하되, "무엇이 무엇보다 먼저/나중인가"는
아래로 확정한다(이월 대상은 기간이지 순서가 아니다).

**4개 앵커(최소 확정, EVAL-ROUND-10 N1 반영 — 대외 런칭 앵커 신설)**:
1. **MVP 착수 = W0 착수**(같은 시점). 05 M1~M12는 이 시점부터 개월 수를 카운트하는 **W축과 독립된 별도 캘린더**다
   — M축은 W단계 진행 속도와 무관하게 흐르며, W단계가 지연돼도 M-count는 멈추지 않는다.
2. **런칭(기술 런칭 — 구독자 웹 공개 시작) = W1 DoD 충족 시점**. 이 "런칭"은 웹 배포·TTFF·OG 렌더 등 **기술 지표
   충족**을 뜻하며, 카톡 채널을 통한 대외 홍보 개시가 아니다(N1 — "기술 런칭 / 대외 런칭 분리", EVAL-ROUND-10
   영역1 감점2·정합성 이슈 J-1·J-2 해소). 대외 홍보 개시 시점은 아래 앵커 4를 따른다.
3. **첫 실 방송 = W2 DoD 충족 이후, 04 §H-1 게이트 전항목 통과 시**(W2와 병렬 구현되는 R10 CF Stream 확인 포함 —
   "완료 전까지 첫 실 방송 개시 금지", 04 §F).
4. **대외 런칭(카톡 채널 공지·홍보 개시) = 시드 콘텐츠 6건(가정 — 지사당 2건 + 센터 제작 2건: 소개·날씨 파일럿)
   확보 시**(N1, ROUND-10-DECISIONS). 공급원 = **첫 촬영 재개**(07 법무 게이트 통과 시점 = "W2 DoD 충족 직전",
   아래 시간축 매핑표 "첫 촬영 재개(전)" 행 참조) **이후의 지사 초기 촬영분 + 센터 자체 제작분**(센터 제작분은
   첫 촬영 재개 이전에도 선확보 가능). 시점별로 시청자가 실제로 보는 콘텐츠·그 출처·지사 온보딩
   시점의 상세는 01 §A-7("전환 기간(W0~W2) 중 서비스 상태" 신설 소절) 인용 — 본 문서는 게이트 수치만 소유하고
   시청 경험 서술은 재정의하지 않는다. **미달 시 대외 런칭 보류**(앵커 2의 기술 런칭 상태로 대기 = 소프트 런칭 —
   구독자 웹은 이미 공개돼 있으나 카톡 채널을 통한 적극 홍보는 개시하지 않는다). 담당: 기획(PM), 판정 시점:
   앵커 2(W1 DoD) 판정과 동시 착수하여 이후 시드 콘텐츠 누적 시마다 재확인(월 1회 W축 진척 점검 회의와 동일
   주기 — 아래 M1~M12 행 참조).

**T-AI 병렬 트랙과의 관계(사실 정정 + 범위 분리, ROUND-2-DECISIONS Y1)**: 이 로드맵(W0~W4)은 **배포 형태 전환**만

`packages/shared`의 잡타입 상수와 media-worker 주석("auto_edit 도입 시 edited_master 추가")뿐 구현이 없다.

  입력)으로 재설계됐으므로(03 §C-2·§C-4 정합화) T-AI를 W2 전에 선행할 이유가 없다.

**커머스 2단계(자체 결제) 트랙과의 관계(ROUND-3-DECISIONS Z1, EVAL-ROUND-3 영역 1 감점 3 해소)**: W2에 등재된

## B. 제온 서버 운영 (전환기 기준 인프라)

- **배치**: 기존 `docker-compose.prod.yml` + `docker-compose.xeon.yml` 오버레이(메모리 리밋·media-worker cpus:8·MinIO) 위에 `web`(nginx 정적) 서비스만 추가. **DCP 파이프라인 공존 규칙(DcpArbiterService — busy 시 미디어 큐 전역 정지)은 그대로** — 정적 서빙·api·라이브 WS는 arbiter 정지 대상이 아니므로 시청·라이브는 DCP 가동 중에도 무중단.
- **외부 노출**: Cloudflare 프록시 뒤에만 노출(오리진 IP 비공개, 방화벽은 Cloudflare IP 대역 + SSH만 허용). ⚠️ 방화벽 개방은 **사용자 승인 후 실행**(기존 결정 유지).
- **백업 (신규 필수)**: ① PostgreSQL 일일 덤프 → R2 별도 버킷(보존 30일) ② 원본·산출물은 R2가 원천이므로 서버 유실 시에도 콘텐츠 무손실 ③ compose·env는 git+비밀은 별도 금고. **복구 리허설을 분기 1회** — 백업은 복구 검증 전까지 백업이 아니다.
- **모니터링**: Uptime Kuma(제온 자체) + 외부 무료 업타임 체크(제온 자체가 죽는 경우 대비) + api `/health/*` + 디스크·RAM 경보(32GB 공유 호스트 — media-worker 리밋 기존 유지).
- **보안사고 대응(신규 필수, 07 §5-7 액션 2 수신 — EVAL-ROUND-8 영역1 감점4 해소)**: 위 가용성 모니터링과 별도로 ① **침해 감지**(비정상 접근·권한 변경 알림) ② **로그 보존**(사고 시 증거 보전, 삭제·덮어쓰기 금지) 2항목을 추가한다. 07 §5-7이 요구한 것은 이 2항목뿐이며 사고 대응 절차 자체(격리·통지·신고)는 07 §5-7 소관으로 08은 구현만 담당한다. 담당: 인프라 담당, 기한: 개인정보처리방침 최초 공개 전(§E 3-2번과 동일).
- **전력·회선 리스크**: 가정/사무실급 회선의 정전·IP 변동 대비 — Cloudflare Tunnel 검토(고정 IP 불요·인바운드 개방 불요, 방화벽 승인 부담도 축소). W0에서 포트 개방 vs Tunnel 중 택1(**권장: Tunnel**). **승인이 W0 착수 + 4주를 넘기면 Tunnel 단독안으로 자동 확정**(§D 리스크 테이블과 동일 규칙).

## C. 클라우드 전환 트리거 (급격히 하지 않는다)

**단일 원천 선언(ROUND-1-DECISIONS X2)**: 클라우드 전환의 **재무 트리거·전면 전환 판단은 [05-monetization.md](05-monetization.md) §C가 유일 원천**이다. 08은 그 수치를 재정의하지 않고 인용만 한다. 08 §C는 05가 다루지 않는 **컴포넌트 단위 조기 이관**(개별 컴포넌트를 전면 전환과 무관하게 먼저 옮기는 것) 기술 트리거만 소유한다.

전환은 **전면 이전이 아니라 컴포넌트별 탈출**로 설계한다(이미 컨테이너·R2·매니지드 라이브라 각 컴포넌트가 독립 이동 가능). 두 층위를 명시적으로 구분한다:

**(A) 전면 전환(전체 컴포넌트) — 05 §C가 소유**: 05 §C의 트리거 **①~⑤**(① 월 총매출 ≥800만원 3개월 연속 / ② `DcpArbiterService` 정지시간 월 누적 10시간 초과 2개월 연속 / ③ 운영 지사 6개 초과 / ④ 다운타임 기대손실(연) > 클라우드 이관 증분비용(연) / ⑤ DCP 경합으로 업로드→프리뷰 p95가 24시간 초과하는 주가 3회 발생) 중 **2개 이상 동시 충족 시** 전면 이관 계획에 착수한다(EVAL-ROUND-2 I-7 정정 — 舊 "①~④"는 05가 실제로 소유한 5개 트리거 중 ⑤를 누락 인용한 오기였다). 08은 이 계획의 실행 창구(§A·§B)만 제공하며 수치를 보유하지 않는다.

**(B) 컴포넌트 단위 조기 이관 — 08 §C가 소유(하나라도 충족 시 해당 컴포넌트만 선제 이관, 전면 전환과 별개)**:
