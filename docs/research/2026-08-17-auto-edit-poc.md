# 자동편집 PoC — 로컬 STT + 로컬 LLM 실측

> 실행일 2026-08-17. 사용자 지시 *"PoC 진행해줘"*(조사 보고 §8 설계대로).
> **모든 수치는 제온 실측이다.** 소재는 실기 촬영본 2건(`movsample/*.MOV`, gitignore).
> 선행 조사: [2026-08-17-xeon-local-llm.md](2026-08-17-xeon-local-llm.md)

## 0. 결론

**로컬 LLM으로 "어느 구간을 남길지" 판단하는 것은 현재 불가능하다.** 4B는 판단을 포기했고(편집 효과 **0%**),
14B는 **13분 걸려 파싱조차 되지 않는 출력**을 냈다. 두 실패의 원인이 다르다는 점이 중요하다 —
4B는 능력 부족, **14B는 출력 길이 제어 실패**이며 후자는 물리적 한계(1.9 t/s)와 겹쳐 완화가 어렵다.

**PoC가 밝혀낸 더 중요한 사실 둘:**

1. **파이프라인의 진짜 약점은 LLM이 아니라 STT다.** 2건 중 **1건(50%)** 에서 Whisper가 반복 루프
   환각을 일으켰고, **어느 로컬 모델도 그것을 전사 실패로 알아보지 못한 채** 사실로 받아들여 제목·요약을
   지어냈다. 쓰레기 입력 위에서는 어떤 모델도 구제되지 않는다.
2. **AI 없이도 자동편집의 상당 부분이 이미 된다.** FFmpeg만으로 무음 제거·음량 정규화(-26.2→-20.0dB)·
   720p 렌디션(132MB→14MB)이 **8.7초**에 끝났다. 결정적이고 테스트 가능하다.

**⇒ 권고: 자동편집을 두 층으로 쪼갠다.** 기계 편집(FFmpeg, 지금 구현 가능) + 텍스트 생성(제목·캡션,
로컬 4B로 17.8초에 쓸 만한 품질). **편집 구간 판단만 보류**한다. 상세는 §6.

## 3. STT 실측 (whisper.cpp large-v3-turbo, 32스레드)

| 대상 | 오디오 길이 | 전사 소요 | 실시간 배속 |
|---|---:|---:|---:|
| IMG_0049 | 63.8s | **35.3초** | 1.8× |
| IMG_0109 | 117.9s | **45.4초** | 2.6× |

속도는 실용 범위다(10분물 ≈ 4분). **문제는 속도가 아니라 정확도다.**

### 3-1. ⚠️ 반복 루프 환각 — 2건 중 1건에서 발생

```
[30.0s-37.0s] 한계의 모든 걸 그곳에 두고 왔다!
[38.0s-41.0s] 한계의 모든 걸 고려하자!
[41.0s-44.0s] 한계의 모든 걸 고려하자!
[44.0s-49.0s] 한계의 모든 걸 고려하자!
[49.0s-52.0s] 한계의 모든 걸 고려하자!
[52.0s-55.0s] 한계의 모든 걸 고려하자!
[55.0s-60.0s] 한계의 모든 걸 고려하자!
[60.0s-64.0s] 한계의 모든 걸 고려하자!
```

동일 문장이 **7회 연속** 반복된다. Whisper의 알려진 실패 모드로, 명확한 음성이 없는 구간에서
모델이 루프에 빠진다. **완화책**(`--temperature-inc`, `--entropy-thold`, VAD 전처리, `--no-speech-thold`)이
있으나 이번 실행에서는 기본값을 썼다 — 운영 전에 튜닝이 필요하다는 뜻이다.

**정상 전사(`IMG_0109`)는 품질이 좋다** — 68세그먼트, 화자 전환과 짧은 응답("네", "응")까지 잡아냈고
제주 방언 **"보말"** 을 정확히 옮겼다.

## 4. EDL 생성 — 3자 비교

세 모델에 **완전히 동일한 messages**(system+user)를 주었다. 프롬프트는 전사본·영상 길이·분류·무음 구간을
입력으로 주고 `title`/`caption`/`summary`/`keep`/`drop` 5개 필드의 JSON 하나만 출력하도록 명시했으며,
"구간이 겹치지 않을 것", "합쳐서 전체를 덮을 것", "전사본에 없는 사실을 지어내지 말 것"을 규칙으로 못박았다.

채점은 인상이 아니라 **기계 검증**(`poc/score.py`)으로 한다: 파싱 성공 · 필수 키 · 구간 겹침 ·
시간 범위 초과 · 커버리지 · 편집 효과.

모든 실행은 `--reasoning-budget 0`(thinking 비활성)으로 조건을 통일했다.

### 4-1. IMG_0109 — 117.9초, 정상 전사 68세그먼트 (실제 방송 후보 소재)

| 모델·모드 | 소요 | 출력 토큰 | 파싱 | 계약위반 | 편집효과 | 판정 |
|---|---:|---:|---|---|---:|---|
| 4B 자유출력 | 26.2초 | 82 | OK | **2건** (keep·drop 키 누락) | 0% | ❌ |
| 4B 스키마강제 | 17.8초 | 136 | OK | 없음 | **0%** | ❌ **판단 포기** |
| 14B 자유출력 | **822초** | 2000(한도) | ❌ **실패** | — | — | ❌ **출력 폭주** |
| 14B 스키마강제 | **772초** | 2000(한도) | ❌ **실패** | — | — | ❌ **출력 폭주** |
| 대조군(프론티어) | — | — | OK | 없음 | 4.4% | ✅ |

**4B는 "자를 것이 없다"고 답했다.** 스키마를 강제하니 `keep: [{0.0, 117.9, "전사본 전체를 포함하여
촬영본의 핵심 내용을 유지"}]` 하나만 냈다 — 프롬프트에 무음 구간(110.3~110.9s)을 **알려줬는데도**
그것조차 빼지 않았다. 형식은 완벽하고(계약위반 0) 내용은 비어 있다.

**14B는 13분을 쓰고 파싱 불가능한 출력을 냈다.** 원인은 판단력이 아니라 **출력 길이 제어 실패**다 —
전사본 68세그먼트를 `keep` 항목으로 **거의 1:1 복사**하기 시작해 2,000토큰 한도에서 JSON이 잘렸다:

```json
{"title":"제주 해변 소라기 잡기", … "keep":[
  {"start":0.0,"end":1.8,"reason":"시작 대사"},
  {"start":4.4,"end":5.8,"reason":"인물 이름"},
  {"start":6.7,"end":7.6,"reason":"질문에 대한 답변"},   ← 전사 세그먼트를 그대로 옮기는 중
  {"start":9.4,"end":10.4,"reason":"질문"}, …            ← 여기서 토큰 소진, 문자열 중단
```

이는 프롬프트로 완화할 여지가 있다("keep 항목은 8개 이하로 병합하라"). 그러나 **속도는 완화되지 않는다** —
출력 2,000토큰 ÷ 실측 1.9 t/s = 1,053초가 물리적 하한이다.

### 4-2. IMG_0049 — 63.8초, 오염 전사 (환각 저항 테스트)

| 모델·모드 | 소요 | 파싱 | 계약위반 | 환각 승계 | 판정 |
|---|---:|---|---|---|---|
| 4B 자유출력 | 12.6초 | OK | 2건 | ❌ 그대로 승계 | ❌ |
| 4B 스키마강제 | 30.1초 | OK | 2건 (64.0s > 63.8s, 커버리지 77%) | ❌ 그대로 승계 | ❌ |
| 14B 자유출력 | 122초 | OK | 2건 (구간 겹침·범위 초과) | ⚠️ 반복은 인식, 제목은 승계 | △ |
| 14B 스키마강제 | 109초 | OK | 2건 (**길이 0 구간** 5개) | ⚠️ 동일 | △ |
| 대조군(프론티어) | — | OK | **없음** | ✅ **전사 실패로 판정** | ✅ |

**14B에서만 의미 있는 차이가 나왔다** — `drop` 사유에 *"중복된 대사"* 를 적어 **반복 자체는 알아봤다**.
4B는 끝까지 알아채지 못했다. 판단력 격차는 실재한다.

**그러나 어느 로컬 모델도 "전사가 실패했다"고 말하지 않았다.** 14B는 요약을
*"한계를 고려하는 메시지가 반복적으로 등장합니다"* 라고 적어 **환각을 사실로 서술**했고, 제목은
`한계의 모든 걸 고려하자`를 그대로 썼다. 프롬프트에 *"전사본만으로 내용을 알 수 없으면 '내용 불명'이라고
솔직히 적는다"* 는 규칙을 명시했는데도 그렇다.

또 하나: 스키마 강제 시 14B가 `{"start":41.0,"end":41.0}` 같은 **길이 0 구간**을 5개 만들었다.
스키마는 타입을 강제하지만 **의미는 강제하지 못한다.**

### 4-3. 반복 관찰된 결함 — 시간 범위 초과

4B·14B 모두 `end: 64.0`을 냈다(영상 길이 63.8초). 전사본 마지막 세그먼트가 `[60.0s-64.0s]`이라
**그 숫자를 그대로 옮긴 것**이다. 근원은 Whisper가 63.8초 영상에 64.0초 타임스탬프를 낸 것이며,
LLM은 그것을 검증 없이 승계했다. **전사 오차가 EDL 오차로 그대로 전파된다.**

## 4-4. AI 없는 기계 편집 실증 (D안)

같은 소재에 FFmpeg만 적용했다(맥 실행, 제온 측정 간섭 회피).

| 항목 | 원본 | 편집본 |
|---|---|---|
| 길이 | 117.86초 | 117.30초 (무음 0.56초 제거) |
| 용량 | 132 MB | **14 MB** (720p 렌디션) |
| 평균 음량 | -26.2 dB | **-20.0 dB** (loudnorm -16 LUFS 목표) |
| 최대 음량 | -4.4 dB | -0.7 dB (헤드룸 활용) |
| **소요** | — | **8.7초** |

**AI 호출 0회, 8.7초.** 무음 제거·음량 정규화·720p 렌디션·faststart가 한 번에 끝난다.
자동편집이 주는 가치의 상당 부분이 여기서 나오며, **결정적이고 테스트 가능하다.**

## 5. 권고 — 자동편집을 두 층으로 쪼갠다

PoC 결과는 "로컬 LLM이 되냐 안 되냐"의 이분법이 아니라 **작업별로 답이 다르다**는 것을 보여준다.

| 층 | 작업 | 수단 | PoC 근거 | 판정 |
|---|---|---|---|---|
| **1** | 무음 제거·음량 정규화·렌디션·faststart | FFmpeg | 8.7초 실증 | ✅ **지금 구현** |
| **1** | 인트로/아웃트로·자막 번인 | FFmpeg | (자산 미비로 미실증, 기술적 확실) | ✅ 지금 구현 |
| **2** | 제목·캡션·요약 생성 | 로컬 4B | 17.8초, 초안 수준 품질 | ⚠️ **초안 생성만**, 사람 확정 |
| **3** | **어느 구간을 남길지 판단** | — | 4B 판단 포기 / 14B 13분·파싱 실패 | ❌ **보류** |

**1층을 먼저 구현할 것을 권한다.** `auto_edit` 워커의 뼈대(큐·잡·`edited_master` 산출·상태 전이)는
어차피 필요하고, 그 뼈대 위에서 1층은 **결정적이라 테스트가 쉽다.** 3층은 뼈대가 선 뒤에 얹어도 늦지 않으며,
그때는 모델 선택지가 지금과 다를 수 있다.

**2층을 붙일 때 지켜야 할 것**: 4B가 만든 제목·캡션은 **초안으로만** 쓰고, 기자 승인 화면에서
수정 가능해야 한다. PoC에서 4B가 만든 캡션은 읽을 만했지만 *"소라기"*(소라게의 오전사)와
*"달팽이"*(비유였는데 사실로 서술)를 그대로 담았다 — **전사 오차가 캡션으로 전파된다.**

### 5-1. 3층(구간 판단)을 재검토할 조건

| # | 조건 | 근거 |
|---|---|---|
| 1 | **STT 신뢰도 확보** — 환각률을 측정 가능한 수준으로 낮춘다(VAD 전처리·`--entropy-thold` 튜닝, 또는 RTZR API) | 현재 2건 중 1건 실패. 이게 안 되면 3층은 무의미 |
| 2 | **메모리 증설**(DIMM 6개) | 14B 생성이 1.9 → 약 7.6 t/s. 13분 → 3.3분 |
| 3 | 출력 길이 제어 프롬프트 확립 | 14B 실패의 직접 원인. "keep 8개 이하로 병합" 등 |
| 4 | 그래도 부족하면 **클라우드 API로 3층만** 위임 | 텍스트만 나가고 원본 음성·영상은 제온에 남는다(조사 §7 C안) |

**지금 시점에서 3층에 자원을 쓰는 것은 이르다** — 1번(STT)이 해결되지 않은 상태에서
모델을 바꿔 봐야 입력이 쓰레기다.

## 6. 재현

```bash
# 오디오 추출(맥) → 제온 전송
ffmpeg -i movsample/IMG_0109.MOV -map 0:a:0 -ar 16000 -ac 1 -c:a pcm_s16le IMG_0109.wav

# 전사(제온)
~/llm-bench/whisper-bin-ubuntu-x64/whisper-cli \
  -m ggml-large-v3-turbo.bin -f poc/IMG_0109.wav -l ko -t 32 -oj -of poc/IMG_0109

# EDL 생성 요청 조립 → llama-server 호출
python3 poc/build_request.py poc/IMG_0109.json 117.9 "culture" "110.3s~110.9s 1곳" > poc/req.json
./llama-b10456/llama-server -m qwen3-14b-q4.gguf -c 8192 -t 32 --host 127.0.0.1 --port 8090 &
curl -s http://127.0.0.1:8090/v1/chat/completions -H "Content-Type: application/json" -d @poc/req.json

# 채점
python3 poc/score.py poc/out.json 117.9
```

제온에 **시스템 패키지 설치는 없다.** 전부 `~/llm-bench/` 안이며 `rm -rf ~/llm-bench`로 완전 원복된다
(실측 13GB: whisper 모델 1.6GB + 4B 2.4GB + 14B 9GB + 바이너리. 루트 여유 353GB).

### 6-1. 실제로 밟은 함정 5개

1. **`pkill -f llama-server`가 자기 SSH 세션을 죽인다** — `ssh xeon '… pkill -f llama-server …'`는
   명령 문자열 자체에 그 패턴이 들어 있어 `-f`(전체 명령행 매칭)가 **부모 셸을 함께 죽인다**(exit 255).
   원격 정리는 패턴을 쪼개거나(`pkill -f 'llama[-]server'`) 별도 단계로 분리할 것.
2. **타임아웃된 `curl`은 서버 생성을 멈추지 않는다** — 클라이언트가 끊겨도 `llama-server`는 계속 토큰을
   만든다. 재시도하면 **두 요청이 32코어를 나눠 써** 측정이 오염된다(실제로 tg가 절반으로 떨어졌다).
   재실행 전 서버를 재시작할 것.
3. **Qwen3의 thinking이 기본 활성** — 요청 본문의 `chat_template_kwargs.enable_thinking=false`만으로는
   확실하지 않다. 서버 기동 시 **`--reasoning-budget 0`**을 줄 것. 안 그러면 출력 토큰이 폭주한다.
4. **zsh에서 `$VAR:linear=true`는 `:l`을 소문자 수정자로 삼킨다** — `-31.96inear=true`가 되어 FFmpeg가
   파싱에 실패한다. 셸 변수는 **`${VAR}`로 감쌀 것**(bash에는 없는 zsh 고유 함정).
5. **`-vf`와 `-filter_complex`는 함께 못 쓴다** — scale을 필터그래프 안으로 넣어야 한다
   (`[vc]scale=-2:720[vo]`).

그 밖에 `/usr/bin/time`이 제온에 없어(`date +%s.%N` 차분으로 대체), `ffmpeg -v error`는
`silencedetect`/`volumedetect` 출력까지 억제한다(`-hide_banner -nostats`를 쓸 것).
