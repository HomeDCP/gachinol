# 운영 보고서 (일간·주간) — 형식 정본

> 사용자 지시 원칙 7: **매일 일간보고서**, **매주 토요일 주간보고서**(일간 요약).
> 읽는 사람은 **사용자 1인**이고, 그가 이 프로젝트에서 하는 **유일한 필수 행동은 결정**이다.
> 그래서 보고서는 **결정을 돕는 것**이어야 하고, 그 외는 전부 부차다.

## ⚠️ 이 형식이 죽지 않게 하는 장치 4개

이 리포에는 **이미 의례화로 죽은 보고 형식이 있다** — `E5-quality-gates.md` §E의 웨이브 종료 보고 7항.
형식은 정교했는데 **Wave 8a 이후 한 번도 작성되지 않았다.** 사인은 셋이었다:
항목마다 문단 크기 · 앵커 16종 재검산이 붙어 작성 비용이 작업보다 컸다 · 읽는 사람의 행동으로
이어지지 않았다.

| 장치 | 내용 |
|---|---|
| **(가) 하드 상한** | 일간 **40행**. 넘으면 항목을 지우지 말고 링크로 뺀다 |
| **(나) 행동 유발** | 맨 위가 **①사용자 결정 대기**. 0건이면 한 줄. 3일 이상 묵으면 제목에 ⚠️ |
| **(다) 자동 소멸** | **연속 3일 변화 없으면 쓰지 않는다** — 다음 일간에 "M/D~M/D 변화 없음" 한 줄. 매일 억지로 쓰는 것이 의례화의 원인이다 |
| **(라) 자기 검증** | 일간 ⑥이 "어제 예정 대비 실제"를, 주간 ③이 그 집계를 낸다. **아무도 안 읽어도 다음 보고서가 모순을 드러낸다** |

## ⭐ 쓰지 말고 생성한다

**④ 지금 상태**는 전부 명령 출력이다 — 사람이 채우지 않는다.
사람(조율자)이 쓰는 것은 **①·③·⑤·⑥**뿐이고, ②는 혼합(커밋 목록 자동 + 결과 문장 사람)이다.
④에 【자동 산출】 표기를 붙이는 이유: **자동은 틀릴 수 없고 사람은 틀릴 수 있다.**
사용자가 **어디를 의심해야 하는지** 알게 하는 것이 "정직 보고"의 실현이다.

> 생성 스크립트는 아직 없다. **대장 #186**(빌드 스탬프 — "배포된 것이 어느 커밋인가"를 묻는 수단)은
> **코드로는 해소**됐으나(2026-08-31, PR #81) **아직 main 미머지**이고, api·워커에는 **자동 배포 경로
> 자체가 없다**(대장 #180 미수신 — web만 merge=자동배포, api는 수동 `compose pull+up`). 즉 지금은
> 코드 부재가 아니라 **머지 + 배포 미완**이 실측 차단자다. 그때까지는 조율자가 **명령을 실제로 돌려**
> 채운다.

### 생성 스크립트 설계 — `infra/scripts/daily-report.mjs` (미구현, 설계 확정)

**선행**: **대장 #186**(빌드 스탬프 — 코드는 해소, PR #81 머지 대기) → 머지 → 제온 api 재배포
(자동화 전이므로 수동, 대장 #180이 그 자동화 자체다). ⚠️ QUEUE 순번(舊 "0-1")이 아니라 **대장 번호로
고정**한다 — QUEUE는 행이 빠지면 순번이 당겨지므로(2026-08-31 renumbering 실례) 순번 참조는 여기서
매번 stale해진다. 이 사슬이 완결되기 전에는 "배포 이미지 나이" 행을 기계가 못 채운다.

**원칙 4개** — 이 리포에서 스크립트가 죽은 방식을 피한다.

1. **읽기 전용.** 조회 명령만 쓴다. 배포·재기동·DB 쓰기는 하지 않는다(`ops-prober`와 같은 계율).
2. **실패를 숨기지 않는다.** 어느 항목을 못 쟀으면 **빈칸이 아니라 `측정 실패: <이유>`**를 쓴다.
   빈칸은 "문제 없음"으로 읽힌다 — 이 리포의 결함이 전부 *"있는 척"*에서 왔다(DISCIPLINES §21).
3. **값과 함께 명령을 쓴다.** 규율 1. 읽는 사람이 그 자리에서 재실행할 수 있어야 한다.
4. **④절만 생성한다.** ①③⑤⑥은 판단이라 조율자가 쓴다. 스크립트가 판단 절까지 채우면
   그 순간 보고서가 의례가 된다(E5 §E가 죽은 방식).

**출력 = ④ 지금 상태 표 한 개.** 행별 산출 방법:

| 행 | 명령 | 실패 시 |
|---|---|---|
| origin/main | `git fetch -q origin main && git log --oneline -1 origin/main` | `측정 실패: 원격 도달 불가` |
| 열린 PR | `gh pr list --state open --json number --jq 'length'` | `측정 실패: gh 인증` |
| CI 3종 | `gh run list --branch main -L 3 --json workflowName,conclusion` | 〃 |
| **배포 이미지 나이** | 각 서비스 `GET /health/version`의 SHA ↔ `git log -1 --format=%cr <sha>` | `측정 실패: /health/version 없음` ← **대장 #186 코드는 해소(PR #81)했으나 머지·배포 전이면 정상 실패다** — 머지+배포(대장 #180) 후에도 뜨면 그때가 진짜 이상 신호 |
| **인터넷 경로** | 살아 있는 터널 호스트로 `curl -s -o /dev/null -w '%{http_code}'` | `측정 실패: 터널 호스트 미상` ← #187의 신호 |
| 테스트 | `pnpm --filter @gachinol/shared build && pnpm --filter <ws> test` | 계수 대신 `측정 실패` |
| 대장 | `node infra/scripts/daejang-recheck.mjs --json` | 〃 |
| 빌드 스탬프 | `grep -rl "GIT_SHA" services/*/Dockerfile` | — |

⚠️ **대장 행은 대장 #182 수리 전까지 신뢰할 수 없다**(舊 "QUEUE 0-2" 참조는 2026-08-31
renumbering으로 **0-1**이 됐다 — 그래서 이제부터 순번이 아니라 **대장 번호로 고정** 참조한다) —
지금 그 스크립트는 대장 아닌 표의 행까지 센다. 수리 전에는 이 행에
**`(#182 미수리 — 총계 신뢰 불가)`를 함께 출력**한다.

**"3일 무변화면 생략"의 판정**: 스크립트가 어제 출력과 diff해 **④가 동일하고 커밋이 0건**이면
`변화 없음`을 반환하고, 조율자가 그날 파일을 만들지 않는다. 연속 3일이면 다음 일간에 한 줄로 합친다.

**주간(토요일)**: 같은 스크립트에 `--weekly`. 그 주 일간 7개를 읽어 **③ 예정 대비 실제**를 집계한다
— 이것이 프로세스가 자기를 교정하는 유일한 루프이므로(④ 판정 오류가 2회 이상이면 QUEUE의 L 사다리를
개정한다), **사람이 세지 않게** 한다.

## 일간 템플릿

```markdown
# 일간 YYYY-MM-DD (요일)

## ① 사용자 결정 대기 — N건
| # | 무엇 | 왜 나에게 오나 | 선택지 | 미결 시 영향 | 대기 |
  ※ "왜 나에게 오나"는 §0-2의 보고 시점 번호로 적는다(③권한 / ④결정).
  ※ 0건이면 "결정 대기 없음" 한 줄.

## ② 어제 무엇이 움직였나
- <슬라이스명> — <한 줄 결과>. 근거: WORKLOG YYYY-MM-DD · PR #N
  ※ 커밋 수가 아니라 결과를 적는다. 상세는 WORKLOG를 참조하고 요약하지 않는다.

## ③ 막힌 것
| 무엇 | 몇 번째 시도 | 다음 조치 |
  ※ 시도 횟수를 적는 이유: 보고 시점 ②(2회 이상 반복)의 발동 장치다.

## ④ 지금 상태  【자동 산출 — 사람의 판단 없음】
| 항목 | 값 | 재현 |
  ※ main · 열린 PR · CI 3종 · 배포 이미지 나이 · 인터넷 경로 · 테스트 · 대장.
  ※ 모니터링 구현이 0%인 동안 이 표가 임시 모니터링이다.

## ⑤ 오늘 예정 — 1건
**<ID>** <제목> (L단 · 규모)
- 왜 이것인가 / 선행 충족 / 동반 의무 / 차단자
  ※ 1건 제한. 실측상 이 팀은 항상 단일 슬라이스로 일한다.

## ⑥ 어제 예정 대비
예정 <X> → 실제 <Y>. 차이 이유: <한 줄>
```

## 주간 템플릿 (토요일)

일간의 **요약이 아니다.** 일간이 못 하는 셋만 한다 — **추세 · 예측 정확도 · 문서 생존**.

```markdown
# 주간 YYYY-Www (MM-DD ~ MM-DD)

## ① 이번 주 한 문장
<전진 / 정체 / 후퇴> — 근거 수치 1개.

## ② 완료 · 미완
| 슬라이스 | 결과 | 근거 |

## ③ 예정 대비 실제  ← 일간 ⑥의 집계
7일 중 일치 N/7. 어긋난 날 사유: ①선행 미충족 ②새 결함 ③사용자 대기 ④판정 오류
→ ★ **④가 2회 이상이면 QUEUE의 L 사다리를 개정한다.** (프로세스가 자기를 교정하는 유일한 루프)

## ④ 지표 추이
| 지표 | 월 | 토 | 변화 |
→ 줄어야 할 것이 늘었으면 그 자리에 사유 한 줄.

## ⑤ 결정 대기 누적
3일↑ ⚠️ / 7일↑는 **그 항목이 막고 있는 태스크 목록**을 함께 적는다.

## ⑥ 다음 주 순서 — 상위 3건
※ 3건만. 4건 이상 적으면 지켜지지 않는다.

## ⑦ 이번 주 배운 것 → 규칙 후보 (0~2건)
| 규칙(1문장) | 근거 실패 | 반영 위치 | 검사 방법 |
※ 0건이면 "없음". 억지로 만들지 않는다. 승인되면 DISCIPLINES.md로.

## ⑧ 문서 생존 점검
30일↑ 무갱신 정본 목록 → 각각 **갱신 / 동결 선언 / 폐기** 중 택1.
※ 이 리포는 계획 문서 4개가 20일 넘게 죽어 있었는데 아무도 사망을 선언하지 않았다.
```

## WORKLOG와의 관계 — 축이 다르다. 둘 다 존치한다

| | `WORKLOG.md` | 일간보고서 |
|---|---|---|
| 축 | **작업(슬라이스)** | **시간(날짜)** |
| 담는 것 | AC · 검증 근거 · 결과 · 이월 · 함정 | 결정 대기 · 시스템 상태 · 막힌 것 · 다음 1건 |
| 빈도 | 슬라이스당 1 | 일 1(변화 없으면 생략) |

**일간은 WORKLOG를 요약하지 않고 참조한다.** 요약하면 둘 다 stale해진다.
