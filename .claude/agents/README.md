## ⭐ 도구 목록이 곧 강제다 (산문이 아닌 유일한 조각)

- **전원 `Agent` 미부여** — 하위 에이전트를 띄울 수 없으면 *"하위 결과를 받았다"*는 거짓 보고가
  **성립 자체를 못 한다.** 2026-08-31 조사에서 실제로 그 사고가 났고(한 에이전트가 자기가 띄운 하위의
  결과를 못 받았는데 받은 것처럼 보고했다), 사고를 낸 것은 `*` 권한을 가진 범용 에이전트였다.
- **`verifier`에 Write·Edit 미부여** — "만든 자 ≠ 검증하는 자"를 프롬프트가 아니라 **능력**으로 강제한다.
  기존 `qa-verifier`가 이 리포에서 유일하게 살아남은 롤인 이유가 이것이다(E1의 8역할 중 나머지 7은 0회 기동).
- **`scribe`에 Write 미부여** — 신규 문서 남발 차단. `exec/`가 1MB로 부푼 전철을 막는다.
- **`planner`에 Bash 미부여** — 계획자가 실행하기 시작하면 계획자가 아니게 된다.

## ⚠️ 로드 시점 제약 (2026-08-31 실측)

**에이전트 정의는 세션 시작 시점에 로드된다.** 세션 중간에 `.claude/agents/*.md`를 새로 만들어도
그 세션에서는 `subagent_type`으로 호출할 수 없다(`Agent type 'planner' not found`).

⇒ **정의를 추가·변경한 뒤에는 새 세션에서 써야 한다.** 그때까지는 범용 에이전트에 그 정의를
프롬프트로 실어 대신 돌린다(같은 규칙이 적용되지만 **도구 제한은 걸리지 않으므로** 위 강제 3종이
무효가 된다는 점을 감안할 것).

## 위임 시 조율자가 반드시 채우는 것

위임문에 **실행 환경 기댓값**을 발주 직전 실측해 적는다. 기댓값이 없으면 불일치를 검출할 대조군이 없다 —
규율 9가 있는데도 워크트리 사고가 2회 난 이유가 이것이다.

```
워크트리 루트 : <git rev-parse --show-toplevel 실측값>
작업 브랜치   : <실측값>
기준 커밋     : <git rev-parse HEAD 실측값>
```

그리고 완료 보고에 **5블록 원문**(환경 증명·산출물·게이트①·미달/미확인/가정·하위 기동 0건)을 요구한다.
**④를 "없음"이라도 명시**하게 하는 것이 핵심이다 — 무언급이 성공으로 읽히는 것이 거짓 보고의 절반이다.

## 조율자의 수신 검증 (보고 1건당 4회, 수십 초)

1. **환경 대조** — 보고 ①블록의 `--show-toplevel`·branch를 발주 기댓값과 문자열 비교
2. **범위 대조** — ②블록의 파일 목록 ⊆ 위임문 소유 파일 집합
3. **★ 주장 1건 무작위 재실행** — ③블록의 명령 중 아무거나 1개를 조율자가 그 자리에서 돌린다.
   값이 다르면 **전건 불신.** 전수 검증 없이 억지력만 얻는 설계다
4. **차단 항목 확인** — ④블록이 "없음"인지 확인. 없으면 **반려**(무언급 = 절차 위반)
